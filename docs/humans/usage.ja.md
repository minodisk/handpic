# Handpic の使い方

Handpic の詳しい動作を説明します。すぐに使い始めるには [README.ja.md](../../README.ja.md) を参照してください。

## 機能

フォルダーはピッカーから開くか、フォルダーまたはその中の任意のファイルをウィンドウにドロップするか、コマンドラインで指定して（`handpic <folder>`）開きます。指定がなければ、前回終了したときに開いていたフォルダーを、見ていたファイルの位置で、前と同じ場所に置いたウィンドウに開き直します。Handpic はその中の RAW ファイル（ARW、CR3、DNG、NEF、ORF、RAF）を一覧にし、埋め込みプレビューを各ファイルの Orientation に従って回転させて順に表示します。フォルダーを開いていないときはビューアの中央に案内が表示され、クリックするとフォルダーピッカーが開きます。設定は `CmdOrCtrl+,` かタイトルバーの右端の歯車で開き、検索欄の付いたページ（`Sidecar`、`Culling`、`Keyboard Shortcuts`、`Cache`、`Import`、`MCP`、`Appearance`、`Updates`）のウィンドウとして表示されます。`Escape` かその `×` で閉じます。`q` で終了します。

- **フォルダー**: 左ペインは、ホームフォルダーとマウント中のボリューム（macOS では `/Volumes/*`、Windows ではドライブレター、Linux では `/mnt/*`、`/media/*/*`、`/run/media/*/*`。これらのルートボリュームの一覧はウィンドウがフォーカスを得るたびに読み直すので、起動後にマウントしたものも Handpic に戻れば表示されます）をルートとするフォルダーツリーです。フォルダーの矢印でサブフォルダーが一覧になり（ただし、すでに最上位にあるものは除くので、ホームがそれを含むボリュームの下に重ねて表示されることはありません）、展開したフォルダーはディスクに追従します。ファイルマネージャー、ほかのアプリ、Handpic 自身がその下でサブフォルダーを作成、削除、名前変更すると、約 1 秒以内に表示に現れたり消えたりします（ネットワーク共有など、アプリが監視できないフォルダーは、もう一度展開したときにだけ一覧し直します）。Windows では、フォルダーを展開している間、ファイルマネージャーはそれを含むフォルダーの名前を変えられません（そのフォルダー自体とその下のフォルダーは自由です）。先に折りたたんでください。展開したフォルダーには、そのフォルダー自体が含む RAW ファイルの数が、RAW ファイルのないフォルダーでは JPEG の数が表示されます（**JPEG だけのフォルダー**を参照）。フォルダー名をクリックすると開きます。ツリーから届かないフォルダーも、`open` キー、空の状態のヒント、ドロップで開けます。開いているフォルダーは強調表示され、どの方法で開いても、フォルダーを開くたびにツリーはそこまで展開されます。ツリーが一覧にしていないボリューム（ネットワーク共有など）上のフォルダーを開くと、そのセッションの間はそのボリュームが最上位に加わります。ツリーをクリックすると、ツリーがキーボードを受け取り、開いているフォルダーにカーソルが置かれます。`ArrowUp` / `ArrowDown` / `Home` / `End` は何も開かずにカーソルを動かし、`Space` はカーソルのフォルダーを展開するか折りたたみ、`Enter` はクリックと同じくそのフォルダーを開き、名前の先頭を入力すると一致するフォルダーに移動します（[キー](#キー)の固定キーを参照）。`ArrowLeft` / `ArrowRight` はツリーのキーではなく、いつもどおりストリップを送ります。ツリーがキーボードを持っている間は、ほかのカリングのキーは効きません。効くのは `open` キー、ストリップの前 / 次、ペインの表示切り替え（デフォルトでは `Alt+Cmd+Arrow` / `Ctrl+Alt+Arrow` と `Tab`）だけで、`Escape`、ほかの場所のクリック、左ペインを隠す操作のいずれかでキーが戻ります。フォルダーを右クリックするとメニューが開き、最初の項目は、そのフォルダーを親フォルダーの中で選択した状態で OS のファイルマネージャーに表示します。macOS では `Reveal in Finder`、Windows では `Reveal in File Explorer`、Linux では `Open Containing Folder` です。その下の `Copy Path` はフォルダーの絶対パスを引用符なしでクリップボードに入れ、`Copy Folder Name` はツリーに表示されている名前を入れます。クリップボードへの書き込みが拒否されると、そのエラーをステータス行に表示します。次の `Refresh` は、展開しているかどうかにかかわらずフォルダーのサブフォルダーと RAW の数を一覧し直し、その下で開いているフォルダーはそのままにして、ツリーのフォルダー監視を設定し直します。監視を設定できなかったフォルダー（ネットワーク共有や、権限が拒否された場合）はそのままではディスクに追従しないので、そのためのものです。一覧できなくなったフォルダーにはそのエラーを表示します。開いているフォルダーそのもの（その上や下のフォルダーではなく）の `Refresh` は、そのフォルダーのファイルの一覧し直しも行います（**フォルダーの変更**を参照）。次の `Rename…`（ホームと最上位のボリュームには表示されません）は、フォルダー名を、名前を選択した状態のテキストボックスに変えます。開いているフォルダーの名前をゆっくり 2 回クリックしても（ダブルクリックではなく、クリックしてから約 0.5 秒後にもう一度クリック）同じことができ、そのクリックでフォルダーを開き直すことはありません。`Enter` で名前を変え、`Escape` で取り消し、ほかの場所をクリックしても名前を変えます。空の名前や変わっていない名前は編集を終えるだけで、編集中はすべてのキーがテキストボックスに入ります。スキャン中に確定した名前変更はスキャンを待ち（ステータス行にその旨を表示します）、スキャンが終わると実行されます。その間、行には新しい名前が薄い色の斜体で時計のアイコン（"Renames when the scan finishes"）の後ろに表示され、フォルダーは元のパスのまま開けます。もう一度名前を変えると待っている名前を編集でき、別の名前にすると置き換わり、元の名前に戻すと名前変更を取り消し、`Escape` か変わっていない名前ではそのまま待ちます。その間に別のフォルダーを開くか、スキャン中に別の操作を押すと、待っている名前変更は取り消され、名前は元に戻り、自分で取り消したときと同じくステータス行に `Rename… was canceled` と表示します。名前が無効、すでに使われている、または OS に拒否された場合は、そのエラーをステータス行に表示し、フォルダーは元のままにします。フォルダーのインデックス、レーティング、フラグ、ラベル、最後に見ていたファイルはフォルダーについていくので、何も抽出し直しません。ツリーの展開状態も保たれ、開いているフォルダーが名前を変えたフォルダーかその下にあれば、新しいパスで、見ていたファイルの位置から開き直します（開き直しなので、取り消し履歴と選択は最初からになります）。次の `Rename by Capture Date…`（これもホームと最上位のボリュームには表示されません）は、フォルダーの名前をその写真の撮影日にするか、撮影日が複数にわたるときは日付ごとの隣のフォルダーに分けます（**Rename by Capture Date…** を参照）。次の `Expand All` は、そのフォルダーとその下のすべてのフォルダーを順に一覧しながら展開します（一覧に失敗したフォルダーはそのエラーを表示し、残りは展開を続けます。シンボリックリンクやジャンクションのフォルダーは祖先に戻ってループすることがあるので、その中には入りません）。`Collapse All` はその下のすべてのフォルダーを折りたたみ、フォルダー自体の開閉はそのままにします。どちらもホームと最上位のボリュームには表示されません。次の `Rewrite Sidecars from Index…` は、Handpic が持っているそのフォルダーの判定をサイドカーに書き戻し、`Delete Sidecars…` はそのフォルダーのサイドカーをゴミ箱に移します（**Rewrite Sidecars from Index… と Delete Sidecars…** を参照）。続く `Sequence JPEG Timestamps…` は、そのフォルダーの JPEG の撮影時刻をプレビューして連番化します（**Sequence JPEG Timestamps…** を参照）。最後の `Import…` はすべてのフォルダーに表示され、その下の写真を日付フォルダーにコピーします（**Import…** を参照）。右クリックではフォルダーを開かず、ツリーにキーボードを渡すことも取り上げることもありません。`Escape` かほかの場所のクリックでメニューを閉じます。
- **フィルムストリップ**: サムネイルはビューアとフォルダーツリーの下、ウィンドウの下端に並び、ページ送りに追従し、クリックしたファイルを表示します。マウスホイールと下端のスクロールバーで横にスクロールします。ヘッダー行の右端には `Sort ▾` と `Filter ▾` のメニューがあり、ヘッダーの上端をドラッグするとストリップの高さを変えられます（起動し直しても保たれます）。ウィンドウ下端のステータス行には位置 `n / N` を表示し、フィルターがオンの間はその後ろの括弧内にフォルダーが一覧しているファイルの数を、複数のファイルを選択している間はさらにその後ろに `· K selected` を表示します。セルのファイル名の帯にポインターを置くとカラーラベルの名前が、スキャンに失敗したファイルのセルに置くとそのエラーが表示されます。フォルダーのスキャン中（`scanning N / M`、続いて `analyzing N / M`）は、ページ送りやスクロールに合わせて、表示中のファイルとストリップに見えているセルを先に処理するので、それらのサムネイル、続いてフォーカスマークが残りより先に届きます。どちらのパスも通常より低い OS の優先度で動き、2 回目のパスはさらに低いので、CPU を取り合うときはビューアとマシンのほかの処理が優先されます。複数のファイルを選択できます。`Cmd+click`（Windows と Linux では `Ctrl+click`）は表示中のファイルを変えずに 1 つのファイルを選択に加えたり外したりし（表示中のファイル自体は常に選択されたままです）、`Shift+click` は最後にクリックしたファイル（アンカー）からクリックしたファイルまでのすべてを選択してクリックしたファイルを表示し、`Shift+ArrowLeft` / `Shift+ArrowRight` はその範囲を 1 ファイルずつ広げたり狭めたりします。`CmdOrCtrl+A` と右クリックメニューの `Select All` は、ストリップに表示されているすべてのファイル（フィルターの結果）を選択します。表示中のファイルはそのまま表示され、アンカーになります。普通のクリックや、別のファイルに移動するキー（矢印キー、連写間の移動）は、選択を移動先のファイルだけにします。選択の外のセルを右クリックすると選択はそのセルだけになり、選択の中のセルなら選択は保たれるので、コンテキストメニューの項目は選択全体に作用します。フィルターで隠れたファイルは選択から外れます。右クリックメニューの `Select All` の下には、右クリックしたファイルを OS のファイルマネージャーで選択した状態で表示する項目（macOS では `Reveal in Finder`、Windows では `Reveal in File Explorer`、Linux では `Open Containing Folder`）と、`Copy Path`、`Copy File Name`（拡張子付きの名前）が並び、右クリックしたファイルのフルパスか名前を、選択中なら選択したすべてのファイルのものを 1 行に 1 つずつコピーします。この 3 つは閲覧専用の JPEG フォルダーでも表示されます。続いて判定の項目（閲覧専用の JPEG フォルダーでは表示されません）が並びます。フラグ（`Pick`、`Unflag`、`Reject`）、スター（5 つから順になしまで）、カラーラベル（7 色と `No label`）で、それぞれにキーが表示され、表示中のファイルが持っているものにはチェックが付きます。選ぶとそのキーと同じことを選択全体に行います。メニューの最後は `Move to Trash…`（右クリックしたファイルが N 個の選択に含まれるときは `Move N Files to Trash…`）で、閲覧専用の JPEG フォルダーでも表示され、右クリックしたファイル、または選択全体をゴミ箱に移します（**Move to Trash…** を参照）。その下の `Delete Permanently…`（`Delete N Files Permanently…`）も同じく閲覧専用の JPEG フォルダーで表示され、それらを移す代わりに削除します（**Delete Permanently…** を参照）。
- **パネル**: macOS では `Alt+Cmd+ArrowLeft`（Windows と Linux では `Ctrl+Alt+ArrowLeft`）で左ペイン（フォルダーツリー）、`…ArrowRight` で右ペイン（メタデータ）、`…ArrowDown` でフィルムストリップの表示と非表示を切り替え、`Tab` で左右両方のペインを一度に切り替えます（Lightroom と同じく、どちらかが表示されていれば両方を隠します）。これで横位置のコマに必要な高さをビューアがすべて使えます。フィルムストリップのヘッダー行も一緒に隠れるので、ストリップが隠れている間はフィルターと並べ替えのメニューも隠れます。どのパネルを隠しているかは再起動後も保たれます。左右のペインとビューアの境目をドラッグすると、そのペインの幅（デフォルトは 220 px）を変えられ、これも保たれます。ウィンドウが両方のペインとビューアを収めるには狭すぎる間は、ペインを狭めて描きます。
- **フォーカスマーク**: `f` で、カメラが記録したフォーカス位置に十字を描きます。カメラが使った AF 枠を記録する Sony のカメラでは、その AF 枠の矩形の中に描きます（デフォルトは非表示）。SIGMA BF のように位置だけを記録するカメラでは十字のみを表示し、M11-P のように何も記録しないカメラやマニュアルフォーカスの写真ではマークを表示しません（[カメラが記録する情報](./cameras.ja.md)を参照）。マークの色は、判定の対象の顔の写り具合を表します。対象は AF 点に最も近い顔で、AF 点がないコマやマニュアルフォーカスのコマでは、Handpic がプレビュー全体で見つけた最も大きい顔です。そのため、そうしたコマも十字は出ませんが明るい緑にもグレーにもなります（状態はストリップのアイコン、メタペイン、フィルターに出ます。AF 点のない集合写真は、その 1 つの顔だけで判定します）。明るい緑は良い写真、つまり失敗ではない可能性が高いコマで、AF の目にピントが合っていること、目が開いていること、顔がカメラを向いていることを同時に満たします。基準は、ファイルのフルサイズの埋め込み JPEG での目のシャープネスが 0.162 以上（小さいプレビューでは隠れる甘さが見えるためで、メタペインの `Eye focus` の行）、目の開き具合（メタペインの `Eyes` の行）が 41 以上、頭の左右の向きが 35° 以内、上下の傾きが 45° 以内です（ロールは見ません）。フェイスメッシュが顔から外れているコマ（寝ている赤ちゃんのように、画面内で大きく回転した顔など）や、顔が画像の端で切れているコマは良い写真になりません。プレビューより大きい JPEG がないファイル（RAF、ORF、HDR PQ の CR3、最大の埋め込み JPEG がプレビューである Sony の α9 II、α7R IV、α7R IVA、α7C、α6400、α6600、ZV-E10）はフルサイズのシャープネスがなく、明るい緑にもグレーにもなりません。プレビューで測るとシャープネスはフルサイズの値の約半分になり、そうしたコマのほとんどがグレーになってしまうためです。シャープネスは目ごとにその周りの正方形の範囲で測り、2 つの目のうちシャープなほうを使います。どちらのしきい値も 1 機種（ILCE-7M5）で決めました。良い写真のしきい値は 3 フォルダーと、別の手作業でラベル付けしたセットで確かめました。後者では、良い写真の 145 コマのうち、作者がしきい値未満でもシャープと判断したのは 5 コマで、シャープなコマが少し良い写真から外れることがあります。高 ISO では甘いコマを見逃します。わざと絞り込んでいるので、ほとんどのコマは明るい緑になりません。作者がピント面が目にあるかどうかで評価した 281 コマ（3 つ星は目にピント、1 つ星は見てわかるほど外れ、2 つ星はその間）では、3 つ星の 154 コマのうち 29 コマがシャープネスの基準だけで外れます。明るい緑は良い写真だけです。グレーは、顔を判定し、その目がフルサイズではっきり甘いコマです。そこでのシャープネスが 0.110 未満の場合で、この値の下には 3 つ星の 154 コマのうち 3 コマと、1 つ星の 88 コマのうち 13 コマが入ります。グレーは失敗のすべてではなく、はっきり甘いコマを拾います。その 281 コマでは、フルサイズのシャープネスは、置き換えたプレビューでの合焦確率よりも 3 つ星のコマをよく見分けました（AUC 0.69 対 0.62。後から評価した別のフォルダーの 58 コマでは 0.74 対 0.64）。それ以外はすべて白です。0.110 以上の顔で良い写真の基準（0.162 未満、または目、顔の向き、メッシュ、画像の端）に届かない場合、フルサイズのシャープネスがないファイル、顔が見つからない場合（AF 点があればその近くに、なければプレビュー全体に）、まだ計算していない場合が当てはまります。顔が見つからないコマはシャープネスのスコアで判定せず白のままにします。作者の顔のない 4361 コマでは、スコアが採用したコマとそれ以外をほとんど見分けられなかった（AUC 0.58）ためです。顔が見つからない、顔が埋め込みプレビュー上で約 60 ピクセル未満のコマは良い写真にならず、大きく横を向いた顔も、意図した向きであっても良い写真になりません。カメラの顔追尾はマークの色に影響しなくなりました。Sony の瞳 AF 枠も、ほかと同じく Handpic が検出した顔で判定します。この状態は、フォルダーのサムネイルとメタデータがそろった直後に始まる 2 回目のパスで計算するので、ステータスに `analyzing N / M` と表示されている間に、画面に見えているファイルから順にマークが白からそれぞれの色に変わります。ストリップでは、明るい緑とグレーのコマのセルの左下、ファイル名の上にマークの色のアイコンが付き、パスが進むにつれて埋まっていきます。良い写真は笑った顔（Lucide の `scan-face`）、グレーのコマはその口を下向きにした顔で、どちらも ISC ライセンス、本文は `crates/app/LICENSE-lucide` です。白のコマには付きません。これは目安であって判定ではありません。背景の人物に AF が合えば顔はシャープになって誤って良い写真になり、後頭部や上を向いた顔は顔が見つからずに白のままです。マークは Handpic が AF 点の近く（AF 点がないときはプレビュー全体）で検出した顔も、シアンの枠と、両目、鼻の先、口の両端のシアンの点、枠の横のラベル（検出スコア、枠の大きさ、両目の間の距離。どちらもプレビューのピクセル単位で、`0.93  212×254  eyes 61` のように表示します）で表示します。検出はコマの表示時に行い、フォルダーを一覧し直すまで保持するので、`f` を押してから少し遅れて現れます。等倍表示では顔を描きません。判定の対象の顔の目はコマの表示時にも判定し直し、その顔には、判定に使った顔のパーツ（輪郭、目、眉、鼻、唇）の線と、目が開いていると判定したときは虹彩の輪と中心の点も、枠より少し遅れて細いマゼンタの線で表示します。スキャンが保存した、目が開いているかどうかとその開き具合は、メタペインの `Eyes` の行に表示します（**メタペイン**を参照）。
- **等倍ピントチェック**: `z` で、フォーカス位置（なければコマの中央）を中心に、フル解像度の画像を画面の 1 ピクセルに 1 画素で表示します。ズーム中にページを送るとズームしたまま、次のファイルのフォーカス位置に移ります。パンや自由なズームはありません。
- **グレースケールプレビュー**: `g` を押している間、構図を判断するために表示中の画像をグレースケールで表示し、離すと色が戻ります。押している間だけの表示上の機能で、何も書き込まず、何も記憶しません。
- **フォーカスピーキング**: `e` で、全体表示と等倍ピントチェックの両方で、表示中の画像の強いエッジを赤く光らせ、ピントの合った面を浮かび上がらせます。もう一度押すと消えます。エッジは画像を描いた大きさで測り、画像が出た少し後に重なります。起動時はオフで記憶しません。`g` を押している間は赤もグレーになります。
- **パフォーマンスグラフ**: `d` で、ビューアの下端に直近 60 秒の 5 つの系列のグラフを表示します。ファイルを切り替えるたびの赤い棒は、その高さがキーやクリックからプレビューが描かれるまでの時間です（凡例の右端の ms の目盛りで、高さは最低 500 ms）。棒は下から段階ごとに赤の濃淡で積み上げられ、`wait`、`read`、`decode`、`orient`、`hop`、`frameWait`、`paint`、`present`（先読み済みのプレビューには `read`、`decode`、`orient` がありません。スキャン中でない間、表示中のファイルの前後のファイルを、ページ送りの方向の次のファイルから読み込んでデコードしておくので、それらに移ると即座に描画されます） の順に並びます。青の太い実線は Handpic 自身の CPU 使用率、青の細い破線はシステム全体の CPU 使用率で、どちらも全コアに対する 0〜100 % です。緑の太い実線は Handpic 自身の読み込み量（凡例の右端の MB/s の目盛りで、高さは最低 10 MB/s）、緑の細い破線はシステムの最も忙しいディスクが使用中だった時間の割合（0〜100 %）です。棒が伸びたら線を見てください。Handpic の CPU の線が高いときは Handpic 自身が忙しく（実行中のスキャンは、解析のパスも含めて Handpic の CPU に数えます）、Handpic の CPU の線が低いままシステムの CPU の線が張り付いているときは、ほかのプロセスが CPU を使っています。CPU の線がどちらも低いままディスクの線が上がっているときは、プレビューがディスクを待っています。RAW ファイルを読んでいるスキャンの後ろで待っていることがよくあります。Windows では Handpic の読み込みの線はディスク以外からの読み込みも含めて数えるので、ぴったり 0 にはなりません。macOS ではディスク使用率の線は表示しません。どの値もグラフを表示している間だけ計測するので、表示するたびに空から始まります。もう一度 `d` を押すと隠れ、起動時はいつも非表示です。
- **判定**: スター、採用 / 不採用のフラグ、カラーラベルです。ストリップのセルに表示され（ラベルはセル下端のファイル名の帯を色付けします）、サイドカーに書き込まれます。[レーティングとサイドカー](#レーティングとサイドカー)を参照してください。複数のファイルを選択しているときは、表示中のファイルから決めた同じ値を、選択中のすべてのファイルに設定します。その判定が触れないフィールドは各ファイルの値のままです（スターのキーは各ラベルをそのままにし、採用は選択中のすべてのファイルの不採用を置き換えますが、各ファイルのスターはそのままです）。隠れているファイルが判定されることはありません。
- **メタペイン**: 値の出どころごとに 3 つのグループに分けて表示します。**EXIF** には、カメラが標準タグに書いたもの（絞り、シャッター、ISO、焦点距離、露出、カメラ、レンズ、撮影時刻）を表示します。**Maker note** には、カメラがメーカー独自のメーカーノートに書いたものを表示します。Sony ではシャッター方式、フォーカスモード、AF エリア（ILCE、NEX、ZV のカメラのみ。FX のシネマカメラ、コンパクトカメラ、A マウントのカメラは除きます）、`Face tracking` や `Lock On AF` などの AF トラッキング、ドライブ（レリーズモード。`Continuous, frame 2` のように連写内のコマ番号付きで表示します）、手ブレ補正、露出モード、測光、クリエイティブスタイル（現行のカメラではクリエイティブルックで、`ST` のような 2 文字のコードで表示されることがあります）、DRO、RAW の種類です。Leica ではフォーカス距離です。古い RX と HX のコンパクトカメラでは、ExifTool が該当しないものとして読むため、フォーカスモードと AF トラッキングを表示しません。Sony のメーカーノートは認識した被写体の種類（人物、動物、鳥、乗り物）や、AF が瞳と顔のどちらに合ったかを記録しないので Handpic も表示せず、暗号化された値（シャッター回数、ピクチャープロファイル）は読みません。`AF tracking` の後には、Handpic が読んだ AF 点（`AF point`。センサーのピクセル単位で、`3120, 2080 of 8640 × 5760` のように表示します）と、カメラが記録していれば AF 枠の大きさ（`AF frame`）が続きます。レンズが F 値を報告しないとき（M11-P に M マウントレンズを付けた場合）、絞りはカメラの推定値で、`(est.)` が付きます。**Analysis** にはスキャンが自分で計算したもの、つまり `Eye focus`（判定の対象の顔（AF 点に最も近い顔。AF 点がないときやマニュアルフォーカスでは、Handpic が確信を持って検出した最も大きい顔）の目のシャープさをファイルのフルサイズの埋め込み JPEG で測ったもので、`Sharp · 0.214` や `Soft · 0.143` のように表示します）を表示します。`Soft` は、そのコマを良い写真から外す判定で、`Face focus` の状態はこの値で決まります。これはスキャンの 2 回目のパスで計算するので、フォルダーを初めてスキャンするときは、ファイルのサムネイルより少し遅れて表示されます。何も測れなかったとき（たとえばプレビューより大きい JPEG がないファイル）は表示しません。`Eyes` は、AF 点に最も近い顔（AF 点がないときは、Handpic が確信を持って検出した最も大きい顔）の目が開いているか閉じているかと、その開き具合を 0〜100 で、`Open · 82` や `Closed · 0` のように表示します。開き具合は、より閉じているほうの目のアスペクト比（まぶたの間隔を目の幅で割ったもの）から求め、Handpic が閉じているとみなす比率以下で 0、大きく開いた目（作者の顔の 90 パーセンタイル）以上で 100、その間は比例します。目がどれだけ開いているかを表すもので、判定の確からしさではありません。閉じているとみなす点をわずかに超えた目は `Open · 0` と表示されます。この行は以下の行とともにスキャンの 2 回目のパスが保存するので、パスがまだ届いていないファイルには表示されません。同梱の [MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker) の顔メッシュ（Apache-2.0、本文と変換の経緯は `crates/core/models/LICENSE-mediapipe`、ローカルで動きネットワークにはアクセスしません）のまぶたの点から求めます。顔がないとき、顔が埋め込みプレビュー上で約 60 ピクセル未満のとき（小さすぎて判定できません）、JPEG ファイルでは表示しません。うつむいた目も瞳が見えないので、まばたきと同じく閉じているとみなします。`Eyes closed` は目が閉じている確率、`Eye aspect ratio` は開き具合を求める元の比です。`Yaw`、`Pitch`、`Roll` は、その同じ顔のヨー、ピッチ、ロールを整数の度で表したものです。ヨーは顔が画像の右を向くとき、ピッチは上を向くとき、ロールは画面上で頭が時計回りに傾くときに正になります。同じ顔メッシュを、MediaPipe の顔ジオメトリと同じ方法で標準の顔モデルに当てはめて求めます（Apache-2.0、経緯は `crates/core/models/LICENSE-mediapipe`）。`Eyes` を表示しないときと、当てはめに失敗したときは表示しません。おおよその向きとして読んでください。手作業でラベル付けした手元の顔では、ヨーとピッチの符号は約 94% で合っていましたが、15〜25° 回した顔は見た目にはまだ正面に見え、横顔に近い顔（約 70° より先。ヨーが 90° を超えて読めることもあります）やスポーツ用サングラスの顔は粗くなります。`Mesh eye offset` と `Edge gap` は、良い写真の基準のうち 2 つの元になる値で、顔メッシュの目が顔検出器の見つけた目の点からどれだけ離れているかと、顔とその目が画像の端にどれだけ近いかです。`Sharpness` はプレビューのシャープネスのスコアです（**シャープネスのスコア**を参照）。
- **フィルターメニュー**: ストリップを、採用フラグ、スター、カラーラベル、向き（`Portrait` / `Landscape`）、フォーカスマークの状態（`Face focus` セクション。各項目には同じ状態のストリップのアイコンが付きます。良い写真、つまり明るい緑のマークと顔アイコンは `Good` で、フルサイズでの目のシャープネス 0.162 以上が基準の 1 つです。白は `Neutral` で、それ以外のすべて、つまり 0.110 以上の顔で良い写真の基準に届かないコマ、プレビューより大きい JPEG がないファイル、顔が見つからないコマ、JPEG、2 回目のパスがまだ届いていないファイルです。グレーは `Low` で、判定した顔のフルサイズでの目のシャープネスが 0.110 未満のコマです。AF 点のないコマも含みます。各ファイルはこのうちちょうど 1 つに当てはまり、複数にチェックを入れるといずれかに当てはまるファイルを表示します。パスが進むにつれてストリップが埋まっていきます）、判定の対象の顔について保存した目の状態（`Eyes` セクション。`Open`、`Closed`、保存した状態のないファイルは `Unknown` で、顔が見つからない、顔が約 60 ピクセル未満、2 回目のパスがまだ届いていないファイルが含まれます）、書き出しの有無（`Output` セクション。後述）、カメラ、レンズ、絞り、シャッタースピード、ISO、焦点距離（`24–35 mm` のような範囲にまとめます）で絞り込みます。カラーラベルのグループには 7 色と `No label` が並びます。その 7 色以外のラベルはどの色の項目にも（`No label` にも）一致しません。向きはファイルの EXIF Orientation で決まります。90 度回転なら縦位置なので、カメラが回転のタグを付けなかったコマは横位置として数えます。`Output` セクションには `Output` と `No output` が並び、書き出さなかった RAW ファイルに絞り込んで、`Select All` と `Move to Trash…` でゴミ箱に移せます。このセクションは、開いているフォルダーの直下に `Output` か `Output-sequenced` のサブフォルダー（PhotoLab の既定の書き出し先と **Sequence JPEG Timestamps…** の書き込み先で、名前の大文字と小文字は区別しません）があるときに表示します。どちらかのフォルダーの直下にあるファイルの語幹（拡張子を除いた名前で、大文字と小文字は区別しません）が、そのファイルの語幹と等しいか、語幹に `_<n>` か `-<n>` を足したもの（PhotoLab のバーチャルコピーで、`DSC0001.ARW` に対する `DSC0001_1.jpg` など）か、語幹に `-DxO` を足したもので始まるもの（DeepPRIME の DNG で、`L1002140-DxO_DeepPRIME 3.jpg` はその DNG と元の `L1002140.DNG` の両方に数えます）であれば、書き出し済みとします。書き出しフォルダーが空のときもセクションは表示され、すべてのファイルが `No output` になります。書き出しフォルダーがなければセクションは隠れ、読み取れないときも隠れてステータス行に理由を表示します。このときセクションのチェックは解除されるので、フォルダーを読めていないファイルが `No output` として表示されることはありません。フォルダーの監視は書き出しフォルダーを対象にしていません。フォルダーを開いている間に書き出したファイルは、フォルダーを一覧し直したとき、つまりツリーで開いているフォルダーの `Refresh` を選んだとき、フォルダー自体が変わったあと、フォルダーを開き直したときに反映されます。EXIF のグループには、フォルダーにある値だけが並びます。グループ内のチェックは OR、グループ間は AND で組み合わされ、`Reset` ですべて解除します。判定で現在のファイルがフィルターから外れると、すぐに隠れ、その後ろでフィルターを通る次のファイルに、なければその前の最後のファイルに、それもなければ空の表示に移ります。採用フラグ、スター、ラベル、向き、`Face focus`、`Eyes` のチェックは起動し直しても保たれ、どのフォルダーにも適用されます。EXIF のチェックは保たれず、フォルダーを開くたびに解除されます。`Output` のチェックはアプリを終了するかセクションが隠れるまで続きます。`Reset` は保たれているフィルターも解除します。
- **並べ替えメニュー**: ストリップを撮影時刻、ファイル名、レーティングのいずれかの順に並べます。ページ送りと `n / N` は選んだ順に従います。撮影時刻が同じときは 1 秒未満の時刻、次にファイル名で決め、撮影時刻のないファイルは最後になります。レーティングは、スターの多い順、次に未評価のファイル、最後に不採用の順で、同じならファイル名で決めます。順序はフォルダーを初めてスキャンする間に確定し、選んだ並べ替えは起動し直しても保たれます。
- **フォルダーを開く**: `open` キー（デフォルトは `CmdOrCtrl+O`）は、空の状態のヒントをクリックしたときと同じくフォルダーピッカーを開きます。
- **フォルダーの変更**: 開いているフォルダーは自動でディスクに追従します。Handpic の外でコピーしたり削除したりしたファイルは、約 1 秒後にストリップに反映されます。ネットワーク共有など変更通知を送らないボリュームでは、ツリーで開いているフォルダーを右クリックして `Refresh` を選ぶと同じことができます。読み直すのは変わった部分だけで、付けたスター、フラグ、カラーラベル、現在のファイル、ストリップの位置はすべてそのままです。
- **Move to Trash…**: フィルムストリップでファイルを右クリックして `Move to Trash…` を選ぶと、そのファイルを OS のゴミ箱に移します。そのファイルが複数選択に含まれるときは `Move N Files to Trash…` になり、選択中のすべてのファイルを移します。`Select All` はフィルターが表示しているものだけを選択するので、不採用で絞り込み、`CmdOrCtrl+A` を押してこれを選べば、フォルダーの不採用を移せます。RAW は隣にあるサイドカーと一緒に移ります。`.xmp` と `.ARW.dop` の両方があれば、現在どちらの形式を選んでいても両方を移します。閲覧専用の JPEG フォルダーでは JPEG だけが移ります。実行前に数だけを確認します（"Move 3 files to the Trash?"）。`Move to Trash` で移動し、`Cancel` か `Escape` では何も変えません。移動中はステータス行に進み具合（`moving to Trash 12 / 300`。Windows では最大 100 個ずつまとめて移すので、数は段階的に増えます）が表示され、その間に別のフォルダーを開いても表示は残り、移動が終わるまでメニュー項目はグレーアウトします。移動が終わると、ストリップは表示していたファイルの隣を表示し、移したファイルは選択から外れ、ステータス行に移した数（"Moved 3 files to the Trash" と、失敗した数）が表示されます。移せなかったものはエラーとして並び、フォルダーに残ります。何も削除しません。ファイルとそのサイドカーはすべてゴミ箱に移るので、戻せばスター、フラグ、カラーラベルも戻ります。スキャン中に確定するとスキャンを止め（止まるまでステータス行にその旨を表示します）、止まり次第移してから、残ったファイルをスキャンします。その間に別のフォルダーを開くと取り消されます。`undo` キー（`CmdOrCtrl+Z`）を 1 回押すと、どのフォルダーを開いていても（何も開いていなくても）移動をまるごと取り消せます。移したすべてのファイルとサイドカーが元の場所に戻り、ステータス行に戻った数（"Restored 3 files from the Trash" と、失敗した数）が表示され、開いているフォルダーが移動元のフォルダーなら、ストリップにファイルが判定とともに再び表示されます。何も上書きしません。元の場所に同じ名前のファイルがある、その後ゴミ箱を空にした、すでに手で戻した、といったファイルはエラーとして並べてそのままにし、戻せなかったファイルのサイドカーもゴミ箱に残ります。別のフォルダーを開いた後も移動は取り消せ、移動と同じく取り消しも実行中のスキャンを待ちます。続けて `redo` キー（`CmdOrCtrl+Shift+Z`）を押すと、戻ってきたファイルをサイドカーと一緒に、ダイアログなしでもう一度ゴミ箱に移します（戻せなかったファイルには触れず、その後元の場所からなくなったファイルはエラーとして並べます）。この移動もまた取り消せます。
- **Delete Permanently…**: ストリップの右クリックメニューで `Move to Trash…` の下にある項目です（N 個の選択では `Delete N Files Permanently…`）。同じファイルを、RAW は隣にあるサイドカーと一緒に、JPEG は単独で、ゴミ箱を通さずに削除するので、ディスクの空きはすぐに増えます。取り消せません。ゴミ箱には何も移らず、取り消しの履歴にもこの操作はありません。ダイアログはそのことを伝え、`Cancel` にフォーカスした状態で開きます。`Enter` でも `Space` でも確定せず、`Delete Permanently` をマウスでクリックしたときだけ実行します。`Cancel` か `Escape` では何も変えません。ステータス行に進み具合（`deleting 12 / 300`）を表示し、終わると削除した数（"Deleted 3 files" と、失敗した数）を表示します。削除できなかったファイルはエラーとして並び、サイドカーとともにフォルダーに残ります。移動と同じく、スキャン中に確定するとスキャンを止め、止まり次第実行してから、残ったファイルをスキャンします。その間に別のフォルダーを開くと取り消されます。どちらかの実行中は、移動も削除も受け付けません。
- **Import…**: フォルダーツリーでフォルダーを右クリックして `Import…` を選ぶと、その下の写真を階層の深さを問わず、コピー先のルートの下に撮影日ごとのフォルダーを作ってコピーします。すでにあるものは飛ばします。メモリーカードもボリュームなので、最上位のボリュームを含むすべてのフォルダーに表示されます。`E:\DCIM\10061024\` の写真が、ファイルマネージャーでのコピーも手での名前変更もなしに `D:\Photos\2026\2026-10-24\` に入ります。日付はカメラが書いた `DateTimeOriginal` のローカルの日付で、タイムゾーンは扱わないので、日付をまたぐ撮影は 2 つのフォルダーに分かれます。元のフォルダーは読むだけで、カードの中身を変更も削除もしません。
  - **設定**: 設定の `Import` ページに 2 つの値があり、どちらも次回の起動後も保たれます。`Destination root` はインポート先のフォルダーで、`Choose…` で選びます。未設定の間はダイアログにその旨を表示し、`Run` は無効です。`Folder pattern` はルートの下のパスで、chrono の strftime の書式で書き、デフォルトは `%Y/%F` です。`%Y` は年（`2026`）、`%y` はその下 2 桁（`26`）、`%m` は月（`10`）、`%d` は日（`24`）、`%b` / `%B` は月の短い名前と完全な名前（`Oct` / `October`）、`%a` / `%A` は曜日の短い名前と完全な名前（`Sat` / `Saturday`）、`%j` は年内の通算日（`297`）、`%F` は `%Y-%m-%d` と同じ（`2026-10-24`）で、`/` はフォルダーの区切りです。それ以外の文字はそのまま使います。ページにはこれらの一覧と、クリックで入力できる例 `%Y/%F`、`%F`、`%Y/%m/%d`、`%Y/%m` があります。`%Y/%m` のように複数の日付が 1 つのフォルダーになるパターンでは、それらの日付は同じフォルダーに入ります。
  - **使えるパターン**: パターンは日付だけです。時刻、タイムゾーン、タイムスタンプの指定子（`%H`、`%M`、`%S`、`%z`、`%s` など）は断ります。未知の指定子、単独の `%`、Windows や macOS が持てないフォルダー名（空、`.`、`..`、`< > : " | ? * \` のいずれかや制御文字を含むもの、末尾が空白かドットのもの）も同じです。入力欄の下の行には今日の写真が入るパスか、赤字で理由を表示します。理由が出ているときは保存済みのパターンがそのまま残ります。`CON` のような予約名は確かめないので、フォルダーを作る時点で OS のエラーとして失敗します。
  - **コピーするもの**: フォルダーとその下のすべてのフォルダー（隠しフォルダーを除く）にある、Handpic が対応する RAW ファイルと JPEG、および各 RAW の既存の `.xmp` と `.dop` のサイドカーです。動画やその他のファイルはコピーしません。RAW の隣の JPEG は独立したファイルとしてコピーします。RAW と JPEG が入ったほかのフォルダーと同じく、日付フォルダーのストリップには RAW だけが表示されます。撮影日を読めないファイルは日付なしで、ダイアログに一覧し、コピーしません。
  - **プレビュー**: 各ファイルの先頭を読む間はステータス行に `reading <folder>…` を表示し、そのあとダイアログに、元のフォルダー、合計、日付順に並べたコピー先フォルダーごとの行（コピーするファイル数とバイト数、飛ばす数）を表示し、続けて衝突するファイル名と日付なしのファイル名をそれぞれ一覧します。数にはサイドカーも含みます。一覧に何があっても、コピーするファイルが 1 つでもあれば `Run` は有効で、なければ何もすることがない理由を表示します。`Cancel` か `Escape` は何も変えずにダイアログを閉じます。
  - **既存のフォルダー**: すでにある日付フォルダーには、足りないものだけを加えます。同じ名前で同じサイズのファイルがあれば、インポート済みとして飛ばすので、同じカードをもう一度インポートしても何もコピーしません。同じ名前でサイズが違うファイルは衝突で、一覧して飛ばし、そこにあるファイルを上書きすることはありません。カメラの連番が `100MSDCF` と `101MSDCF` をまたいで一周したときのように、同じフォルダーへ向かう同じ名前のファイルが 2 つあれば、2 つ目も衝突です。比べるのは名前とサイズだけでハッシュは取らないので、同じ長さのままその場で編集されたファイルはインポート済みとして扱います。サイドカーは RAW に従います。衝突する RAW の隣のサイドカーも衝突で、飛ばす RAW の隣のサイドカーは、なければコピーし、あればサイズにかかわらずそのままにします。Handpic が書き換えている可能性が高いためです。この確認は各ファイルを書き込む直前にも行います。プレビューのあとで現れたファイルは、予定のサイズなら飛ばし、そうでなければそのファイルは失敗になり、いずれの場合もそこにあるものはそのまま残ります。
  - **書きかけのファイル**: 各ファイルは日付フォルダーの中に `<name>.handpic-tmp` として書き込み、フラッシュして元のファイルの更新日時を設定してから本来の名前に変えるので、ストリップにもスキャンにも書きかけのファイルは見えません。
  - **インポート中のカリング**: `Run` は日付フォルダーを作り、ファイルが入る最初の（最も早い日付の）フォルダーをすぐに開きます。ほかのフォルダーを開いていても開き、そのフォルダーのスキャンは止まります。フォルダーツリーはそのフォルダーを表示します。フォルダーは最初はすでにあるファイルだけを表示し（新しいフォルダーなら空）、ファイルが届くにつれて埋まります。ストリップが伸びても表示中のファイルはそのままで、それまでの判定も保たれます。ほかの日付フォルダーにファイルが届いてもストリップは変わりません。
  - **進行状況と中止**: 実行が始まるとダイアログは閉じ、ステータス行に `importing N / M` を表示します。もう一度 `Import…` を選ぶと、どのフォルダーからでも、別のインポートを始めずにダイアログが戻ります。実行を止めるのはその `Cancel` だけで、すぐに止まり、コピー中のファイルは破棄されます（次のインポートでコピーされます）。それまでにコピーし終えたファイルは残り、次のインポートで飛ばされます。`Escape` はダイアログを閉じるだけで、実行は続きます。終わるとステータス行に `Imported N files (X MB)`（1 GB 以上は `X GB`）または `Import canceled, N files copied` を表示し、該当するものがあれば `, K already there` と `, J failed` を続けます。Handpic のウィンドウがアクティブでない間に実行が終わると、`Import finished`（中止したときは `Import canceled`）という題で同じ要約を OS の通知に表示し、それをクリックするとウィンドウが前面に出ます。Windows と macOS では、次のインポートの通知がこれを置き換えます。失敗したファイルは右ペイン下部のエラー一覧に `name: reason` の形で並び、ほかのファイルのコピーは続きます。インポートに取り消しはありません。コピーしたファイルは、ほかのファイルと同じく `Move to Trash…` で片付けます。
  - **インポート中にできること**: フラグ、レーティング、カラーラベルは、日付フォルダーでもほかのフォルダーでも使えます。ただし JPEG だけの日付フォルダーは閲覧専用で（**JPEG だけのフォルダー**を参照）、RAW ファイルが入ってから使えます。`Move to Trash…`、`Delete Permanently…`、設定、`Rename…`、`Rename by Capture Date…`、`Rewrite Sidecars from Index…`、`Delete Sidecars…`、`Sequence JPEG Timestamps…` は実行が終わるまで受け付けません。名前の変更はステータス行に `Rename… is unavailable while an import runs` と表示します。
  - **スループット**: 実行のたびに `Handpic.log`（**ログファイル**を参照）にスループットの行を 1 行書きます。MB は 10^6 バイトです。`import: files=120 bytes=5280000000 mb_per_s=41.2 skipped=3 failed=0 canceled=false source=E:\DCIM root=D:\Photos in 128155ms` のような行です。Handpic はファイルマネージャーより速くコピーできるとはうたっていません。計測の内容と比べ方は[メモリーカードからのコピー](./performance.ja.md#メモリーカードからのコピー)を参照してください。
- **Rename by Capture Date…**: フォルダーツリーでフォルダーを右クリックして（ホームと最上位のボリュームには表示されません）`Rename by Capture Date…` を選ぶと、フォルダーの名前をその写真の撮影日にします。カードの `100MSDCF` をカリングの前に手で撮影日に変える手間を省くためのものです。日付はカメラが書いた `DateTimeOriginal` の、タイムゾーンを考えない現地の日付で、`YYYY-MM-DD`（例: `2026-10-31`）の形になります。そのため、日付をまたぐ撮影は 2 つの日付になります。数えるのはフォルダー直下のファイル、つまり RAW ファイル（JPEG だけのフォルダーでは JPEG）だけで、サブフォルダーは探しません。撮影日を読めないファイルは日付なしです。実行前にダイアログで確認します。`Run` で実行し、`Cancel` か `Escape` では何も変えず、ファイルの移動中はボタンが無効になります。
  - **日付が 1 つ**: ダイアログはファイル数とともに `Rename <name> to 2026-10-31?` と尋ね、`Run` は `Rename…` とまったく同じようにフォルダーの名前を変えます。日付なしのファイルとサブフォルダーも一緒に移り、インデックス、判定、最後に見ていたファイルもフォルダーについていきます。
  - **日付が複数**: ダイアログは日付フォルダーごとに 1 行、ファイル数とともに一覧します。`Run` は元のフォルダーの隣（その親フォルダーの中）にそれらのフォルダーを作り、日付のある各ファイルをその日付のフォルダーに移します。RAW ファイルは `.xmp` と `.dop` のサイドカー（あるもの）と一緒に、JPEG は単独で移ります。星、フラグ、カラーラベル、サムネイル、メタデータもファイルについていくので、何も抽出し直しません。日付なしのファイルは元のフォルダーに残り、ダイアログに一覧されます。サブフォルダーも残ります。移せなかったファイルは元の場所に残ってそのエラーが一覧され、ほかのファイルは移ります。元のフォルダーが空になれば削除し、それが開いているフォルダーだったなら代わりに最初の日付フォルダーを開きます。空にならなければ残し、ステータス行に、そこに残った項目（ファイルとサブフォルダー）の数を表示します（`Split <name> into 2026-10-31 (120), 2026-11-01 (45); <name> kept (2 left)`）。
  - **断る場合**: 何もマージしません。対象の名前のフォルダーやファイルがすでにフォルダーの隣にあると、ダイアログはそれを赤で表示して `Run` を無効にします。フォルダーがすでにその 1 つの日付の名前のときも同じです。分割では、フォルダー自体と同じ名前の対象もすでに使われているものとして扱うので、2 つの日付の写真を含む `2026-10-31` というフォルダーは分割しません。日付のある写真が 1 枚もないフォルダーはステータス行で断り、スキャン中に選んだときもスキャン中のメッセージで断ります。スキャンが終わってから選び直してください。一部だけ分割できたあとに、残ったフォルダーでもう一度実行すると、日付フォルダーがすでにあるので断ります。
  - **取り消し**: 名前変更や分割そのものは取り消せません。分割の前に行った `Move to Trash…` は分割のあとも取り消せますが、ファイルは日付フォルダーではなく元のフォルダーに戻り、元のフォルダーが削除されていれば取り消しは失敗してエラーとして一覧され、ファイルはゴミ箱に残ります。
- **Rewrite Sidecars from Index… と Delete Sidecars…**: フォルダーツリーでフォルダーを右クリックすると、そのフォルダーのファイルについて Handpic が持っている判定をサイドカーに書き戻したり、サイドカーをまとめて取り除いたりできます。書き込みが失敗したとき、ほかのプログラムがサイドカーを上書きしたとき、サイドカー形式を切り替えたときなどに使います。どちらも、現在選択しているサイドカー形式（`Both (.xmp and .dop)` なら両方）の、フォルダー内の RAW ファイルの隣にあるサイドカーだけが対象で、サブフォルダーには作用しません。どちらも実行前にダイアログで確認します。`Cancel` か `Escape` では何も変えず、実行中はボタンが無効になります。JPEG だけのフォルダーはステータス行で断ります。スキャン中に選ぶとスキャンを待ち（ステータス行にその旨を表示します）、スキャンが終わると確認します。
  - `Rewrite Sidecars from Index…` はフォルダーのインデックスの内容を書き込むので、Handpic で一度開いたフォルダーである必要があります。一度も開いていないフォルダーでは、ステータス行に `No judgments indexed for <name>; open the folder first` と表示します。ダイアログには、判定のあるファイル、判定のないファイル（既存のサイドカーをレーティングなし、フラグなし、ラベルなしに戻し、サイドカーがなければ作りません）、インデックスがまだ知らない RAW ファイル（飛ばします）の数が並び、`Rewrite the XMP sidecars of N files in <name>?` と確認します。既存のサイドカーは作り直さずに書き換えます。変わるのはレーティング、採用 / 不採用のフラグ、カラーラベル（と `.dop` の 2 つのタイムスタンプ）だけなので、Lightroom の現像設定や PhotoLab の補正は 1 バイトも変わりません。判定があってサイドカーのないファイルには新しく作ります。終わるとステータス行に `Rewrote the sidecars of N files in <name>` と、失敗した数が表示されます。失敗した書き込みはメタペインのエラーに並び、次にフォルダーを開いたときにやり直します。ストリップはすでにインデックスの内容を表示しているので変わりません。
  - `Delete Sidecars…` は、開いたことがあるかどうかにかかわらず、どのフォルダーでも使えます。ダイアログには形式ごとのサイドカーの数とサイズ（`12 XMP sidecars (48 KB)`）が並び、`Move N sidecars (size) of <name> to the Trash?` と確認します。`Move to Trash` でサイドカーを OS のゴミ箱に移し、ステータス行に `Moved N sidecars to the Trash` と、失敗した数が表示されます（失敗はそれぞれ、その RAW ファイルのエラーとしてメタペインに並びます）。RAW ファイルがなくなったサイドカーには触れません。Handpic はそれらのファイルの判定を忘れるので、そのフォルダーを開いていれば、ストリップからスター、フラグ、カラーラベルがすぐに消えます。フォルダーにその形式のサイドカーがないときは、ステータス行にそう表示します（`No XMP sidecars in <name>`）。**Move to Trash…** と同じく、`undo` キーを 1 回押すとサイドカーが戻り（`Restored N sidecars from the Trash`）、そのフォルダーを開いていれば判定も戻ります。`redo` キーでもう一度ゴミ箱に移します。
- **Sequence JPEG Timestamps…**: フォルダーツリーでフォルダーを右クリックして `Sequence JPEG Timestamps…` を選ぶと、その中の書き出し済み JPEG の撮影時刻を秒単位で重ならないようにします。`SubSecTimeOriginal` を無視する Google フォトでも、連写が撮影順に並びます。Handpic でカリングし、残した写真を RAW 現像ソフトから JPEG で書き出したら、ツリーで書き出し先のフォルダーを右クリックします（[lapse](https://github.com/minodisk/lapse) v0.4.0 から派生したものです）。
  - **ファイル**: フォルダー直下の `.jpg` / `.jpeg` ファイル（大文字小文字を問いません）が対象で、サブフォルダーは探しません。1 つもないフォルダーはエラーになり、ステータス行に表示します。
  - **並び順**: `DateTimeOriginal`、次に `SubSecTimeOriginal`（小数として比べるので `5` は `12` より後です。ない値や不正な値は 0 として扱うので、その秒の中で最初に並びます）、次にファイル名の自然順（`DSC2` が `DSC10` より前）で決まります。そのため、2 台のカメラから書き出したフォルダーや、`9999` から `0001` に戻った Sony の連番でも、撮影順に並びます。
  - **新しい時刻**: 最初のファイルは時刻をそのまま保ち、以降の各ファイルは `max(its own time, the previous file's new time + 1 s)`（自分の時刻と、前のファイルの新しい時刻 + 1 秒の大きい方）になります。同じ秒にまとまったコマだけがずらされ、ずらした時刻が追いつけば、後の場面は時刻をそのまま保ちます。
  - **タグ**: `DateTimeOriginal`（0x9003）を書き換え、ファイルに `DateTimeDigitized`（0x9004）と `DateTime`（0x0132）があれば同じ時刻にします。タグを新しく作ることはありません。19 バイトの値をその場で上書きするので、画像データを含めほかのバイトはすべて同一のままです。
  - **プレビュー**: ダイアログに、計算した順にすべてのファイルを `old -> new` の形で並べ（新しい `DateTimeOriginal` の変わる部分は緑で、`DateTimeOriginal` が変わらないファイルは薄く表示します）、続く 2 行で出力先フォルダーに書き込むファイルの数（読めたすべてのファイル。例: `247 files will be written to Output-sequenced`）と、そのうち撮影時刻が新しくなる、つまり緑になるファイルの数（例: `68 of them get a new capture time`）を示し、読めなかったファイル、出力先フォルダーを表示します。`<folder>-sequenced/` がすでにあるときは、作り直す（その JPEG ファイルを置き換える）旨の通知を表示します。`Run` で書き込み、`Cancel` か `Escape` では何も変えずに閉じます。
  - **出力**: 元のファイルには一切書き込みません。すべてのファイルを、右クリックしたフォルダーの隣の `<folder>-sequenced/` に同じ名前で書き込みます。時刻が変わらないものも書き込むので、出力は完全なコピーになります。各ファイルは一時ファイルに書いてから名前を変えて配置します。もう一度実行すると、元の時刻から出力を作り直します。まず `<folder>-sequenced/` 直下の `.jpg` / `.jpeg` ファイルを削除する（ほかのファイルとサブフォルダーはそのまま）ので、ファイルを追加、削除、名前変更した後でも、出力は常に元のフォルダーと一致します。リンク経由などで出力先フォルダーが元のフォルダーと同じ場所を指すときは、実行を拒否します。コピーは元のファイルの更新日時やパーミッションを保ちません。
  - **進行状況と中止**: 実行中はステータス行に `sequencing done / total` を表示します。`Cancel` か `Escape` で次のファイルの前に止まります。そのとき出力先フォルダーにはそれまでに書き終えたファイルだけが残り、次の実行で作り直されます。終わるとステータス行に `Wrote N of M files to <folder>-sequenced`、中止した場合は `canceled, N of M written` を表示し、失敗したファイルがあれば `, K failed` が続きます。ファイルを書き込んだ実行の後は、フォルダーツリーの表示項目と同じく、`<folder>-sequenced` を親フォルダーの中で選択した状態で OS のファイルマネージャーに表示します。中止した後やファイルを 1 つも書き込まなかったときは表示しません。
  - **失敗**: `DateTimeOriginal` を読めないファイルは新しい時刻もコピーも得られません。プレビューでは並び順の下に `name: reason` の形で理由とともに並び、1 つも読めなかったときは `Run` が無効になります。実行中に読み書きできずに失敗したファイルは、ダイアログが閉じた後に右ペイン下部のエラー一覧に `name: reason` の形で並び、ほかのファイルは書き込まれます。
- **JPEG だけのフォルダー**: **Sequence JPEG Timestamps…** の出力の `<folder>-sequenced/` のように JPEG だけが入ったフォルダーは、ストリップで閲覧専用で開くので、ほかのアプリを使わずに並び順と撮影時刻を確かめられます。
  - **対象のフォルダー**: フォルダー直下の `.jpg` / `.jpeg` ファイル（大文字小文字を問いません）は、そのフォルダーに RAW ファイルが 1 つもないときだけ一覧にします。RAW ファイルが 1 つでもあるフォルダーでは RAW ファイルだけを一覧にするので、RAW+JPEG で撮ったフォルダーのストリップが 2 倍になることはありません。フォルダーツリーの数も同じ規則に従い、JPEG だけのフォルダーには JPEG の数を表示します。
  - **表示されるもの**: サムネイル、プレビュー（JPEG 全体を EXIF Orientation に従って回転したもの）、`z` の等倍表示、JPEG の Exif から読んだメタペインの **EXIF** の行です。**Maker note** の行、シャープネスのスコア、フォーカスマークと顔検出はなく、`f` は何も描きません。フォルダーを開いている間、メタペインの下部の注記に `JPEG folder: view only` を表示します。
  - **並び順**: 常に撮影時刻順（並べ替えメニューの撮影時刻順と同じく、同じなら 1 秒未満の時刻、次にファイル名で決めます）で、Exif や撮影時刻のない JPEG はファイル名順で最後に並びます。並べ替えメニューは無効になります。RAW フォルダー用に選んだ順序は適用も変更もされないので、次の RAW フォルダーはその順序で開きます。
  - **無効になるもの**: スター、フラグ、カラーラベルのキー、`c`（すべて消去）、`Shift+x`（連写の残りを不採用）、判定の `Undo` / `Redo` は何もしません（`Move to Trash…` とその取り消しとやり直しは使えます）。ストリップの右クリックメニューには `Select All`、ファイルを表示する項目、`Copy Path`、`Copy File Name`、`Move to Trash…`、`Delete Permanently…` だけが表示されます。移動、選択、フィルターメニュー、パネルの切り替えは使え、フォルダーはほかと同じく最後に見ていたファイルの位置で開き直します。MCP の `set_judgment` ツールは `culling does not apply to a JPEG folder` で拒否され、ほかのツールは使えます。
  - **サイドカー**: 読み込みも書き込みもしません。`foo.jpg` の隣の `foo.xmp` や `foo.jpg.dop` は無視し、JPEG の隣に何かを書き込むことはありません。
- **Undo**: `undo` キー（デフォルトは `CmdOrCtrl+Z`）は、最後に判定したファイルのレーティング、フラグ、カラーラベルを判定前の状態に戻し、それをサイドカーに書き込んで、そのファイルに戻ります（フィルターで隠れるようになった場合は戻らず、ステータス行にその旨を表示します）。繰り返し押すとさらに前に戻ります。選択中の複数のファイルへの判定は 1 回で取り消されます。連写の残りの不採用（`Shift+x`）も 1 回で取り消され、不採用にしたすべてのコマを戻し、現在のファイルにとどまります。判定の履歴は開いているフォルダーのもので、別のフォルダーを開くか、サイドカー形式を変えるか、キャッシュを消去すると消えます。`Move to Trash…` は同じ履歴の 1 ステップで、フォルダーを切り替えても残ります。取り消すとゴミ箱からファイルを戻し（**Move to Trash…** を参照）、さらに押すとそれより前の判定まで戻れます。
- **Redo**: `redo` キー（`CmdOrCtrl+Shift+Z`）は、最後に取り消した判定を同じようにもう一度適用します。取り消した `Move to Trash…` の後では、戻ってきたファイルをダイアログなしでもう一度ゴミ箱に移します。やり直しの履歴はファイルをもう一度判定した時点で消え、取り消しの履歴と同じく、別のフォルダーを開くかサイドカー形式を変えると判定の分は消えます。
- **ログファイル**: Handpic はログを `Handpic.log` に書きます（上限は 1 MB で、ローテーション時に以前の内容は破棄され、別のファイルとしては残りません）。場所は Windows では `%LOCALAPPDATA%\dev.minodisk.handpic\logs\`、macOS では `~/Library/Logs/dev.minodisk.handpic/`、Linux では `~/.local/share/dev.minodisk.handpic/logs/` で、`--log <path>` で別のファイルを指定することもできます。
- **自動送り**: 設定の `Culling` ページの `Auto-advance after a star, reject or pick` がオン（デフォルトはオン）のとき、`1`-`5`、不採用、採用、不採用または採用を外す操作は、次のファイルに移ります。ファイルがすでに持っている値を押した場合も（値はそのままで何も書き込みません）移るので、すでに正しいファイルが続くところは同じキーで確定していけます。最後のファイルは選択されたままです。判定によって有効なフィルターから外れたファイルはすでにカーソルを次のファイルに渡しているので、2 つ先に進むことはありません。選択中の複数のファイルへの判定では移りません。
- **Clear Cache**: 設定の `Cache` ページには、フォルダーのインデックスが使っているディスク容量が表示され、`Clear Cache` で確認の後に空にします。これまでに開いたすべてのフォルダーのキャッシュ済みのサムネイルとメタデータを削除します。判定はサイドカーにあるので影響を受けません。サイズはファイルマネージャーと同じ単位で表示します（macOS では 10 進、Windows と Linux では 2 進）。スキャン中に押すとスキャンを待ちます。スキャンが終わり次第キャッシュを消去する旨の注記が表示され、その後消去が自動で実行されます。設定を閉じると保留中の消去は取り消されるので、消去が実行されるのはスキャンが終わるまで設定を開いたままにしたときだけです。サイズの数値はスキャンが終わるたびに更新されます。消去の後は開いているフォルダーを一覧し直します。消去しなくても、キャッシュは 1 か月開いていないフォルダーを削除します。ただし表示した（約 0.5 秒画面に出た）ファイルか不採用のあるフォルダーは残し、1 GB の上限を超えると、開いたのが最も古いフォルダーから削除します。
- **シャープネスのスコア**: Handpic は RAW ファイルごとのシャープネスのスコアを埋め込みプレビューから計算します。カメラが顔追尾を記録していればカメラの瞳 AF 枠で、そうでなくカメラが AF のフォーカス位置を記録していればその周辺で取り、コマのほかの場所に顔が見つかってもそうします。AF 点がないとき（マニュアルフォーカスや、何も記録しないカメラ）に限り、検出した顔の目を、それもなければコマの中で最もシャープな領域を使います。顔と目は同梱の [YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet) モデル（MIT ライセンス、本文は `crates/core/models/LICENSE`）で検出し、ローカルで動いてネットワークにはアクセスしません。スコアはフォーカスマークの状態と同じ 2 回目のパスで計算し、メタペインの `Sharpness` の行に表示し、MCP クライアント（`get_view` と `get_photo`）にも渡します。スコアは被写体のピントではなく AF 点の下の質感を追うため、何にも色を付けません。作者の、良い写真（フォーカスマークの明るい緑）を含む 1717 の連写では、最もシャープなコマが良い写真だったのは 47.6% で、ランダムなコマは 45.8%、最初のコマは 55.0% でした。[カメラが記録する情報](./cameras.ja.md)を参照してください。
- **連写**: 直前のコマから 1 秒以内に撮ったコマは連写になります。まとまりは選んだ並べ替えにかかわらず撮影順に従い、1 秒未満の撮影時刻を記録しないカメラのファイルは秒単位でまとめます。カメラ自身のシャッターを押すごとの連番ではなく、あえて時刻に従ってまとめています。連写は 1 つの瞬間であり、1 つの瞬間は、プリキャプチャーのコマに続く全押しや素早い押し直しのように、何度かのシャッターにまたがることがよくあるからです。2 コマ以上の連写では、ストリップのセルの背後の色付きの帯がそのコマをつなぎます。帯のどのセルにも、連写内のコマの位置と連写の枚数（`3/7`）が表示されます。これは撮影順で連写全体について数えるので、フィルターや並べ替えでコマが隠れたり離れたりしても数字は変わりません。`ArrowDown` で次の連写の最初のコマに、`ArrowUp` で現在の連写の最初のコマ（すでにそこにいれば前の連写の最初のコマ）に移ります。`Alt+ArrowLeft` / `Alt+ArrowRight`（macOS では `Option`）で現在の連写の中を 1 コマずつ移動し、表示されている最初と最後のコマで止まります。`Shift+x` は、フィルターで隠れているコマも含め、現在の連写のほかのすべてのコマを不採用にし、1 回の取り消しですべて戻ります。[カメラが記録する情報](./cameras.ja.md)を参照してください。

フォルダーツリーがキーボードを持っている間は、`open`、`previous`、`next`、`toggleStrip`、`toggleLeft`、`toggleRight`、`toggleSides`（デフォルトでは `Cmd+O` / `Ctrl+O`、`ArrowLeft` / `ArrowRight`、`Alt+Cmd+Arrow` / `Ctrl+Alt+Arrow`、`Tab`）だけが、どのキーに割り当てられていても実行され、ほかのアクションはツリーがキーボードを手放すまで無視されます。下のツリー自身のキーが優先され、印字可能な文字はすべてツリーでの名前の入力になるので、これらのアクションのどれかを普通の文字（たとえば `l`）に割り当て直すと、ツリーがキーボードを持っている間は実行されません。

## レーティングとサイドカー

RAW ファイルには一切書き込みません。判定は RAW の隣のサイドカーに、2 つの形式のどちらか、または両方で書き込みます。どれを使うかは設定の `Sidecar` ページで選びます（選ぶまでは Lightroom (XMP) です）。

- **Lightroom (XMP)**: `FOO.ARW` に対して `FOO.xmp` を作ります。`xmp:Rating`（`0`-`5`）、採用 / 不採用のフラグを表す `xmpDM:good`（採用は `True`、不採用は `False`、どちらでもなければなし）、カラーラベルを Lightroom と同じく `photoshop:LabelColor` と `xmp:Label` の両方で持ちます。`xmp:Label` には設定でその色に付けた名前（デフォルトは英語の `Red`、`Yellow`、`Green`、`Blue`、`Purple`）を、`photoshop:LabelColor` には小文字の英語の色名（`red` など）を書きます。名前は同じページで編集でき、その `Lightroom language` の一覧で Lightroom のメニューの言語を選ぶと、名前をその言語のデフォルト（日本語なら `レッド` ... `パープル`）にします。一覧には、使っている名前の言語が表示されます。`xmp:Label` が設定した名前か英語の名前に一致するサイドカーは、その色で表示します。
- **PhotoLab (.dop)**: `FOO.ARW` に対して `FOO.ARW.dop` を作ります（`FOO.NEF` なら `FOO.NEF.dop`、`FOO.ORF` なら `FOO.ORF.dop`、`FOO.RAF` なら `FOO.RAF.dop` と、RAW の拡張子を残します）。スター、採用 / 不採用のフラグ、PhotoLab 10 が読む `ColorLabel` の行（`Red`、`Orange`、`Yellow`、`Green`、`Blue`、`Pink`、`Purple`）を持ちます。
- **Both**: すべての判定を、それぞれ上と同じ形で `FOO.xmp` と `FOO.ARW.dop` に書き込みます。フォルダーを開いたときは 2 つのうち最後に更新された方を読む（同時なら XMP）ので、Lightroom と PhotoLab のどちらで後から編集してもその編集が優先されます。ファイルのラベルを知らずに行った判定は、その新しい方のサイドカーのラベルを保って両方に書きます。2 つのファイルはそれぞれアトミックに書き込みますが、まとめてではありません。一方の書き込みに失敗すると、セッション中の再試行で判定を両方にもう一度書きます。失敗した試行のたびに、書き込めた方のサイドカーを記憶しておくので、再試行の間や再試行を使い切った後にフォルダーを開いても、その先の書き込みを外部の編集と取り違えることなく、判定を両方に書きます。

ラベルを消すと、`photoshop:LabelColor` と `xmp:Label`、または `ColorLabel` の行を削除します。ラベルなしはフィールドがない状態です。ラベルはサイドカーが持つ文字列のまま保たれます。もう一方のツールの語彙の名前は変えずに書き戻してその色で表示し、それ以外の名前（たとえば Lightroom のカスタムラベル）はグレーで表示します。

ほかのツールが書いたサイドカーはその場で編集します。変えるのはレーティング、フラグ、ラベルだけで、それ以外（現像設定、キーワード）はすべてバイト単位でそのまま保ちます。サイドカーのないファイルを消去しても、サイドカーは作りません。

書き込みはバックグラウンドでアトミックに行うので、クラッシュしても書きかけのサイドカーが残ることはなく、終了時には保留中の書き込みを済ませます。書き込めなかった判定（たとえばロックされたカード）は、その後 30 秒ほどの間に何度か再試行し、それでも失敗すれば保持して次にフォルダーを開いたときに再試行します。エラーは別のフォルダーを開くまで右ペインの下部に表示し、フォルダーを開いたときにアプリが読めなかったサイドカー（壊れている、または 4 MiB を超える）も同じく表示します。ほかのツールが編集したサイドカーは次にフォルダーを開いたときに読み込み、両方が変わっていればほかのツールの編集が優先されます。形式を切り替えても書き込んでいない判定は保たれ、新しい形式（または両方）で書き込みます。選ばなくなった形式のファイルはそのままにし、Both に切り替えても何も書き換えないので、判定し直すまでは 1 つのファイルの 2 つのサイドカーの内容が食い違うことがあります。

フォルダーのインデックスはキャッシュですが、書き込んでいない判定も持っているので、インデックスのスキーマが新しくなったときは以前のものを捨てずにその場で移行します。移行できないバージョンだけを破棄し、サイドカーから作り直します。

## MCP コンパニオン

Handpic は [MCP](https://modelcontextprotocol.io/)（Model Context Protocol）のエンドポイントを提供でき、AI アシスタントなどの MCP クライアントがカリングに付き添えます。Handpic が表示している内容を読み、小さなプレビューを見て、表示を動かし、判定を記録し、メニューの操作を始められます。デフォルトはオフです。設定の `MCP` ページの `Let MCP clients connect` をオンにするとサーバーが起動し、オフにすると止まります。再起動は要りません。オンの間は起動のたびにもサーバーが始まります。新しい設定ストアは、以前のインストールの値を引き継ぎます（[インストール](#インストール)を参照）。MCP クライアントがこの設定を変えることはできません。

- **エンドポイント**: `http://127.0.0.1:41917/mcp` で、Streamable HTTP で提供します。`MCP` ページにこのアドレスが表示され、選択してコピーできます。サーバーが動作中か、停止中か、起動できなかったかも表示されます。起動できないとき（たとえばほかのプログラムがポート 41917 を使っている）は、ページに理由が表示され、次の起動で再び試せるようスイッチはオンのまま残り、Handpic 自体は動き続けます。すぐに再び試すには、スイッチをオフにしてからオンにします。
- **ローカル専用**: サーバーはループバックアドレスで待ち受けるので、このコンピューター上のプログラムしか接続できず、Web ページからのリクエストが持つ `Origin` ヘッダー付きのリクエストはすべて拒否します。トークンはありません。オンの間は、このコンピューター上であなたとして動いているものなら何でも接続できます。
- **簡単に戻せない操作はあなたが確認する**: クライアントが求めたゴミ箱への移動、そのやり直し、フォルダーの操作（サイドカーの書き直しや削除、連番化、インポート、撮影日による名前変更）、フォルダーの名前変更、キャッシュの消去は、Handpic 自身のダイアログ（フォルダーの名前変更では、名前を入れたツリーの名前変更欄）を開いてあなたの確認を待ちます。設定の `MCP` ページで `Let MCP clients run destructive operations without asking` をオンにすると（デフォルトはオフ）、クライアントはダイアログが示すはずのプレビューを受け取り、確認の 2 回目の呼び出しで実行します。完全な削除は常にあなたのクリックを待ち、この設定をクライアントが変えることはできません。RAW ファイルには一切書き込みません。
- **メインウィンドウが応答する**: どのツールもメインウィンドウの状態を読むか変えるので、ほとんどのツールを役立てるにはそこでフォルダーを開いておく必要があり、ウィンドウが 5 秒以内に応答しなければ呼び出しは失敗します（`wait_for_idle` は自身のタイムアウトまで待ちます）。

| ツール | 動作 |
|------|--------------|
| `get_view` | Handpic が表示している内容。開いているフォルダー、フィルターが残す写真の数、現在の写真とその位置、選択、表示モード（`normal` か `zoom`）、並べ替えの順序、フィルターのチェックとそのフォルダーで選べる項目、表示中のペインとオーバーレイ、現在の写真の連写と各コマのシャープネスのスコア、スター、フラグ、ラベル、現在の写真の `eyes`（目が開いているか閉じているか、閉じている確率（0〜1）、頭の向き（ヨー、ピッチ、ロールを度で表したもの。符号はメタペインの `Yaw`、`Pitch`、`Roll` と同じで、当てはめに失敗したときは null））。判定する顔がないとき `eyes` は null で、写真を表示して少し後に判定し終えるまで（JPEG だけのフォルダーでは常に）`eyes` はありません |
| `get_photo` | 1 枚の写真のスター、フラグ、ラベル、シャープネスのスコア、AF 点と AF 枠、マニュアルフォーカスかどうか、向き、撮影時刻、撮影設定（カメラ、レンズ、絞り、シャッター、ISO、焦点距離、露出補正、フォーカス距離）。パスを指定しなければ現在の写真 |
| `get_preview` | 1 枚の写真の、正しい向きの小さな JPEG。埋め込みプレビューから（RAW からは決して作らず）長辺 1024 ピクセル、または 256 から 1616 の指定したサイズに縮小したもの |
| `show_photo` | フィルムストリップでクリックしたときと同じく、1 枚の写真を表示する |
| `select_photos` | 写真の一覧を選択し、最初の 1 枚を表示する |
| `navigate` | ページ送りのキーと同じく、前 / 次、最初 / 最後の写真、または連写や連写内のコマ単位で移動する |
| `select_all` | フィルターが表示しているすべての写真を選択する |
| `set_view` | `z` と同じく、フィット表示と等倍ピントチェックを切り替える |
| `set_judgment` | 指定した写真、指定しなければ選択のスター（`0` で消去）、フラグ（`none`、`pick`、`reject`）、カラーラベル（`Red`、`Orange`、`Yellow`、`Green`、`Blue`、`Pink`、`Purple`、または消去する null）を設定する |
| `reject_rest` | `Shift+x` と同じく、現在の写真の連写のほかのコマを不採用にする |
| `undo` / `redo` | キーと同じく、最新の変更を取り消す、またはやり直す（ゴミ箱への移動のやり直しは上のとおり確認する） |
| `set_sort` / `set_filter` | メニューと同じく、ストリップの順序やフィルターのチェックを設定する |
| `set_panes` / `set_overlays` | ペインの表示を切り替える、またはフォーカスマーク、フォーカスピーキング、パフォーマンスグラフ、グレースケール表示をオン / オフにする |
| `list_folders` / `open_folder` / `tree_folder` / `reveal` | ツリーのルートやフォルダーのサブフォルダーを一覧する、フォルダーを開く、ツリーの行を展開、折りたたみ、一覧し直す、フォルダーや写真をファイルマネージャーで表示する |
| `get_status` / `wait_for_idle` | ステータス行とペインの注記の内容、実行中か最後に終わった操作、保留中のプレビューを返す。または何も実行中でなくなるまで待つ |
| `trash_photos` | 指定した写真、または選択をゴミ箱に移す、または完全に削除する |
| `rewrite_sidecars` / `delete_sidecars` / `sequence_timestamps` / `import_folder` / `rename_by_capture_date` / `rename_folder` | フォルダーツリーの同じ名前の操作 |
| `cancel_operation` | ダイアログの `Cancel` と同じことをする、または連番化かインポートの実行を止める |
| `get_settings` / `set_settings` | 設定ウィンドウと同じく設定を読む、または変える（確認なしの実行を許すスイッチは除く） |
| `clear_cache` | `Cache` ページの `Clear Cache` |

写真は開いているフォルダーのものでなければならず、写真を表示、選択、判定するツールはフィルターで隠れた写真を拒否します。`set_judgment` は判定のキーと同じ経路を通ります。指定しなかったフィールドは各写真の値のままで、ストリップはすぐに更新され、変更は取り消しの 1 ステップになり、サイドカーはキーを押したときと同じように書き込まれます。自動送りは適用されません。サーバーの指示は、アシスタントに判定を提案させ、書き込むのはあなたが頼んだときだけにするよう求めています。比較、`recommended` の並べ替え、ジャンルのフィルター、ファイルの名前変更、ランキングの学習し直し、AI のスイッチを求めると拒否されます。このアプリにはまだないためです。

Streamable HTTP で MCP を話すクライアントなら、上のエンドポイントに接続できます。例を 2 つ挙げます。

- **Claude Code**:
  `claude mcp add --transport http handpic http://127.0.0.1:41917/mcp`
- **Claude Desktop**: `claude_desktop_config.json` に次を追加します。`npx -y mcp-remote` を経由するので Node.js が必要です。ローカルのサーバーに対して Claude Desktop が `url` を直接書く形を受け付けるかは検証していません。

  ```json
  {
    "mcpServers": {
      "handpic": {
        "command": "npx",
        "args": ["-y", "mcp-remote", "http://127.0.0.1:41917/mcp"]
      }
    }
  }
  ```

## インストール

現在のアプリのパッケージはまだリリースしていません。それまでは、[CONTRIBUTING.md](../../CONTRIBUTING.md)（英語）の手順でソースからビルドしてください。[Releases ページ](https://github.com/minodisk/handpic/releases)のパッケージ（Handpic がまだ Riffle という名前だった 1.10.0 まで）は、このアプリが置き換えた以前のアプリのもので、このアプリへはアップデートされません。

新しくインストールしたときに以前のインストールから引き継ぐもの:

- **設定**: 設定は OS の設定フォルダー（Windows では `%APPDATA%`、macOS では `~/Library/Application Support`、Linux では `~/.config`）の `dev.minodisk.handpic` の下の `settings.sqlite` に保存します。このファイルがまだないときは、同じ設定フォルダーの `dev.minodisk.handpic`、なければ `com.minodisk.handpic`、なければ `com.minodisk.riffle` の下にある以前のインストールの `settings.json` から一度だけ値を取り込みます。サイドカー形式、ラベル名、キー、自動送り、並べ替え、保存したフィルター、MCP のスイッチ、インポート先とパターン、ペイン、最後のフォルダー、ウィンドウの位置です。そのファイルは読むだけで、変更しません。
- **判定**: RAW ファイルの隣のサイドカーにあるので、フォルダーを開くたびに戻ります。
- **フォルダーのインデックス**: キャッシュで、OS のキャッシュフォルダーの `dev.minodisk.handpic` の下の `index.sqlite` に保存します。新しいインストールでは、フォルダーを開くにつれて作り直します。

## アップデート

パッケージからインストールした Handpic は、GitHub にあるプロジェクトのリリースから自分でアップデートします（まだ 1 つも公開していません。上を参照してください）。ソースからビルドしたものはアップデートされず、新しいバージョンがあることを知らせるだけです。

- **確認するとき**: 起動時（ただし 1 時間に 1 回まで。最後に確認した時刻は設定と一緒に保存します）と、設定の `Updates` ページで `Check for Updates` を押したときです。このページには、実行中のバージョン、このコピーのインストール方法、アップデートの状態（確認中、ダウンロード中とその割合、検証中、再起動待ち、失敗とその理由）が表示されます。確認やダウンロードに失敗しても Handpic はそのままです。もう一度 `Check for Updates` を押して試してください。
- **確認なしで**: 新しいバージョンがあると、Handpic はそれを自分でダウンロード、検証、インストールし、再起動を待ちます。ペインの注記と `Updates` ページにその旨が表示され、そのページの `Restart Now` で新しいバージョンとして再起動します。勝手に再起動することはありません。再起動は通常の終了と同じように終了するので、新しいバージョンが起動する前にすべての判定がサイドカーに書き込まれます。
- **インストール方法ごとの動作**:
  - **Windows のポータブル ZIP**: Handpic の実行中にフォルダー内の `handpic.exe` を置き換え、`Restart Now` で新しいものを起動します。置き換えるのは実行ファイルだけで、`licenses` フォルダーは展開したときのままです。
  - **Windows のインストーラー**: 新しいバージョンのセットアップをバックグラウンドでダウンロードし、Handpic の終了時にサイレントで実行します。インストールはそのユーザーだけに行い、管理者の確認は表示されません。`Restart Now` は終了してインストールさせ、新しいバージョンを起動します。普通に終了したときはインストールだけを行い、何も起動しません。
  - **macOS の `Handpic.app`**: 中のファイルではなく、アプリ全体を置き換えます。新しいアプリを古いアプリの隣に展開し、署名を確かめてから 2 つを入れ替え、`Restart Now` で開きます。そのため `Handpic.app` は `/Applications` など書き込めるフォルダーに置く必要があります。ディスクイメージから、またはダウンロードフォルダーから直接開いたときは、`/Applications` に移すよう求めるメッセージでアップデートが失敗します。
  - **Linux の `install.sh` でインストールした `.tar.gz`**: ポータブル ZIP と同じように `~/.local/bin/handpic` を置き換えます。アイコンとデスクトップエントリーはインストールしたときのままです。
  - **Linux の `.deb`**: 何もインストールしません。`Updates` ページに利用できるバージョンが表示され、`Open Release Page` でそのリリースを開きます。そこにある `.deb` を最初と同じようにインストールしてください（`sudo apt install ./handpic_<version>_amd64.deb`）。
- **検証**: Handpic がインストールするダウンロードはすべて、リリースの `SHA256SUMS` と、プロジェクト自身の鍵による署名で確かめます。その公開鍵は Handpic に組み込まれています。どちらかの確認に通らないダウンロードはインストールしません。Handpic は Apple や Microsoft の署名を受けていないので、アップデートがプロジェクトから来たことを示すのはこの鍵です。
- **プレリリース**: `2.0.0-rc.1` のようにプレリリースの部分があるバージョンは、それ自体がプレリリースのコピーにだけ提供します。プレリリースのコピーには、新しいバージョンであれば後のプレリリースも正式リリースもすべて提供し、正式リリースにアップデートした後は正式リリースだけを受け取ります。正式リリースのコピーにプレリリースを提供することはありません。
