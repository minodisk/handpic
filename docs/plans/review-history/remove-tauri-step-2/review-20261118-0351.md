### Findings

1. **[crates/native/src/logger.rs:32]**: The binary rename changes what the debug filter lets through. `enabled` keeps a sub-`INFO` line when `metadata.target().starts_with(env!("CARGO_CRATE_NAME"))`. The crate name used to be `riffle_native`, which shares no prefix with `riffle_backend` or `riffle_core`. It is now `handpic`, which is a prefix of `handpic_backend::*` and `handpic_core::*`. So under `RUST_LOG=debug`, the backend's debug lines now reach stderr and `Handpic.log` (for example `log::debug!` in `crates/backend/src/photolab.rs:108`). That contradicts `docs/agents/app-log.md:192-193` ("`handpic`'s lines of that level only, not the backend's or GPUI's") and the doc comment above `Logger`. Suggested fix: match the crate exactly or as a module-path prefix, e.g. `target == env!("CARGO_CRATE_NAME") || target.starts_with(concat!(env!("CARGO_CRATE_NAME"), "::"))`. Add a unit test that keeps a `handpic::scan` debug line and drops a `handpic_backend::photolab` one, so a later rename cannot break this again. Also add this to the Step 2 learnings next to the existing note about the `log` target.
