### Findings

1. **[install.sh:71]**: `arch="$(uname -m)"` reports `x86_64` on an Apple Silicon Mac when the shell runs under Rosetta, for example a terminal set to "Open using Rosetta" or an x86_64 Homebrew shell. The script then installs the Intel build. That build runs translated, and it stays Intel because the updater picks its asset from the compile-time architecture (`crates/engine/src/update.rs:262-269`). This defeats the "Apple Silicon or Intel" promise in the docs. Fix: on Darwin, use `arm64` whenever `sysctl -n hw.optional.arm64 2>/dev/null` prints `1`, and otherwise keep the `uname -m` value.
2. **[docs/plans/20261124-install-scripts/plan.md:228]**: Step 1 is ticked, but `## Progress` is empty. The plan's `<pr-rules>` require the implementation PR to include "the plan.md update (marking the step done + the Progress entry)". Fix: add a Step 1 entry to Progress. It should say what landed, that the macOS and Linux checks were done, and that the Windows manual check of `install.ps1` is still open (see `learnings.md`).
