### Findings

1. **crates/native/src/main.rs:2044-2160 (`tree_row_clicked` / `reveal`)**: `reveal_collapsed` can go stale and override a later request. If an "open and collapse" click lands while `gate.in_flight()`, `open` only stores `deferred_open` and returns, so `reveal_collapsed` stays set until the deferred open runs. Any other open of the same folder in that window inherits the collapse, because `reveal` takes the field and compares paths only. That includes a second click on the now-collapsed row (`RowClick::Open` -> `open_from_tree` overwrites `deferred_open` with the same folder), `Enter` on it (`TreeCommand::Open`), or a pick or drop of it. The user's latest request was "open and expand", but the reveal leaves the row collapsed. The plan's Step 1 asks to verify that the deferred-open path does not "leave stale state behind". The doc's claim that "any other reveal drops it" also does not hold here, because those opens do not reveal until the run ends. Fix: let the last request win by clearing `self.reveal_collapsed = None` in every open other than the `OpenCollapsed` arm: at the top of `open_from_tree` (this covers the `Open` click, `Enter` and the import's first folder), and before `open` in `pick_folder` and `drop_paths`. The alternative is to pass the intent into `open` and store it next to `deferred_open`. Then add a sentence to the `docs/agents/native-app.md` rule saying that a later open of the same folder drops the field.
