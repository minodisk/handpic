## Round 1

**Reviewed commit**: `5221aa8ced01689e9588bbd4d9c7c197e90257fb` feat(native): hold the decoded neighbours in a prefetch ring

STATUS: NEEDS_FIX

### Findings

1. **[crates/native/src/pager.rs:83]**: `finish` checks `index == self.index` before `self.hit`, so a ring hit on the file whose own page read is still out gets `Finished::Current`, and `loaded` shows that file a second time. This can happen. Start on file 1 with a prefetch of 2 in flight. Press Next to 2: the hit misses because 2 is pending, not held, so a page read of 2 goes out. Press Next to 3 before either read lands: `plan(3)` wants `[4, 2]`, so the prefetch of 2 settles into the ring. Press Previous to 2: `take_held` hits and calls `show_held` and `pager.hit()`. Then the page read of 2 lands as `Current`, and `show_current` runs again: a second `present` (the ring's copy is retired through `keep`), `analyze_current`, a restarted `start_dwell` that delays the viewed mark, `hold.hold` waiting on a paint, and `zoom.shown`. This breaks the plan's "a ring hit while an older read is still out does not re-read the file that is already shown", and the `native-app.md` rule that `Pager::hit` makes the older result `Dropped`. Fix: in `finish`, check `self.hit` first (`if self.hit { self.in_flight = false; Finished::Dropped }` before the `index == self.index` arm), and add a pager test that runs `request() == Some(1)`, `go(Next)`, `go(Previous)`, `hit()`, then expects `finish(1, true, ..) == Finished::Dropped` and `!in_flight()`.

## Round 2

**Reviewed commit**: `eb17e9dc5167201afc124506419d0413c821a43e` fix: address local review round 1 findings

STATUS: NEEDS_FIX

**Previous feedback**: addressed 1 / dismissal accepted 0 / re-raised 0

### Findings

1. **[crates/native/src/main.rs:1772 (`go`) and :1322 / :1329 (`refilter`)]**: When the ring has the file, `zoom.shown` gets the previous page's `seq`. `go` calls `self.request(key, cx)` before `self.zoom_page(cx)`. On a ring hit, `request` runs `take_held`, then `show_held`, then `show_current`, then `self.zoom.shown(focus, orientation)`. That stamps the facts with the old `seq`, and `zoom_page` bumps `seq` right after. So `Zoom::preview()` is `None` for that page for as long as it stays current. `refilter`'s `moved` branch has the same order: `request` first, then `zoom_page`. With zoom on, a page reached through the ring never gets the scaled-preview placeholder in `zoom_paint`, even after its own crop arrives (`placeholder_fits` is true then, but `preview()` is not). The read path does not have this problem, because its result lands after `zoom_page` has already bumped `seq`. This also goes against the `native-app.md` rule that `zoom.shown` "stamps the facts with the current page's `seq`", and against the plan's claim that a hit does everything a current result does. Fix: call `self.zoom_page(cx)` before `self.request(..)` in `go`, and in `refilter`'s `moved` branch. `zoom_page` only needs `pager.current()` and `files`, and both are already updated at that point. Alternatively, have `show_held` defer `zoom.shown` until after the page bump. Add a short note in the prefetch section of `native-app.md` that the page bump must come before `request`, because a hit shows the image synchronously.
