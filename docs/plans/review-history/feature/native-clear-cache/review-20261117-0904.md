### Findings

1. **crates/native/src/main.rs:2417 (`drain_clear`) / main.rs:2242 (its only call site in `finished`)**: A held clear is drained only from `Riffle::finished`. But `clear_busy()` also counts `gate.in_flight()`, and several in-flight runs end by releasing `resync` through `resync.finished()` directly, with no listing or scan after it, so `Riffle::finished` is never called. Examples are `restored` (main.rs, the `else if self.resync.finished()` arm, reached after a trash undo into a folder other than the open one), `folderops.rs`'s `settle_folder_run` (a failed rename, and a rename with no folder open, which does not even `resync.hold()`), and this PR's own `cleared` failure / no-folder arms. Here is a reachable case: press `ctrl+z` to undo a large trash run of another folder, open the settings with `ctrl+,` (it is not blocked while a trash step is in flight), then press `Clear Cache`. The press is held (`Waiting`), the restore ends, and the view is idle, but nothing drains the hold. The page keeps showing `WAITING_NOTE`, and a second press is ignored because `ClearFlow::press` returns `Wait` for any state other than `Idle`. The only way out is to close the settings or wait for an unrelated scan. That breaks the Done-when rule that "the clear goes on by itself when the view becomes idle". Suggested fix: call `drain_clear(cx)` wherever `gate.leave_in_flight()` / `resync.finished()` leave the view idle without starting a listing. One way is a small helper used by `restored`, `settle_folder_run`, the trash/rename ends and `cleared`'s non-relisting arms. Another is for `press_clear` to drain at once when the flow is already `Waiting` and `clear_busy()` is now false. Add a test for the second part in `cache.rs` if you take it, e.g. `press(false)` while `Waiting` returning `Ask`.
