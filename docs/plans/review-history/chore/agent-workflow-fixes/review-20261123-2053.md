1. **[.claude/agents/local-review-runner.md:66-71]**: The new missing-section rule in "2. Decide" can deadlock the runner. Under the new "Dispatching a child" section, the runner only reaches "2. Decide" *after* the reviewer's hand-back has arrived. If the `## Round {round_n}` section is still missing at that point, for example because the reviewer handed back without writing (it crashed, wrote to the wrong path, or reported an error), the rule says "End your turn and wait for the reviewer's hand-back, then read the file again". That hand-back has already been consumed and no second one will come, so the runner hangs with no terminal state. The rule should cover both cases. If the hand-back has not arrived yet (the async launch returned early), end the turn and wait. If the hand-back has arrived and the section is still missing or has no `STATUS:` line, treat it as a child failure and report it to the caller, per "About the child agents" ("Treat a child's failure as your own failure and report it"). Do not wait again.

2. **[.claude/skills/pr/scripts/wait-pr-actionable.sh:23-27, 71-80; .claude/agents/pr-runner.md:261-264; .claude/agents/merger.md:77-80]**: The docs claim that "one exit 1 stands for an outage as long as the slice", but the code does not do that. The script exits 1 whenever the slice's *last* call fails, whether or not earlier calls in the same slice succeeded. With the `60 60` slice the agents now pass, a slice has only two calls. So one failed `pr-status.sh` at elapsed 60 s, right after a successful call at 0 s, already exits 1. That is the blip this item was meant to absorb. Because `pr_status_failures` resets only on exit 0, sporadic single failures that land on the second call add up across a long wait of up to 15 slices toward the `> 5` abort. The test named "fails through the whole slice" (`wait-pr-actionable.test.sh:154`) has the same problem: its first call succeeds (`ACTION=wait`), so it pins "last call failed", not "whole slice failed". Pick one of these fixes:
   - (a) Keep the last successful output. When the slice ends on a failed call after at least one success, exit 2 with that output, so the attempt counts as ordinary waiting. Exit 1 only when every call in the slice failed. Add a test for the success-then-failure case (exit 2), and change the "whole slice" case to fail on every call.
   - (b) Keep the current behavior. Correct the header comment and the two agent bullets to say that exit 1 means the slice's last call failed, not that the outage lasted the whole slice. Rename the test to match, and reconsider whether `pr_status_failures > 5` is still the right ceiling.

   (a) matches the item's goal better.
