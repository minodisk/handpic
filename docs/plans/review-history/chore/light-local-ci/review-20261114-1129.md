### Findings

1. **[tools/ci/local.sh:80, 297, 300]**: The script needs bash 4+ (`local -A packages=() tests=() scripts=()` in `select_checks`, `mapfile -t selected` in `main`), and no other `*.sh` in the repository does. On macOS the `bash` a mise `shell = "bash -c"` task finds is `/bin/bash` 3.2 unless Homebrew bash comes first on `PATH`. There, `local -A` fails with "invalid option", so `mise run ci:local` breaks. `mise run lint` and `mise run ci` break too, because `[tasks.lint]` now runs `bash tools/ci/local.test.sh`, which calls `local.sh --select`. GitHub's `lint` job runs only on Ubuntu, so CI never shows this, but `CONTRIBUTING.md` lists macOS as a development platform and now describes `ci:local` for contributors. Fix: make the script bash 3.2 compatible. Keep the selected packages, tests and scripts in newline-separated strings deduplicated with `sort -u`, or in plain indexed arrays, and replace `mapfile` with a `while IFS= read -r` loop. Then run `local.test.sh` under a 3.2 shell to confirm. If that is not wanted, add an explicit guard at the top (`(( BASH_VERSINFO[0] >= 4 ))`, otherwise a clear message naming the requirement) and state the requirement in `CONTRIBUTING.md`.
2. **[tools/ci/local.sh:309-321]**: Three `printf` calls in `main` have a format string with a raw newline inside single quotes (`printf '%s` / `' ...`). The rest of the file writes `'%s\n'`. It works, but it is hard to read and easy to break when the file is reformatted. Write `printf '%s\n'` as everywhere else in the file.
3. **[tools/ci/local.sh:43-56]**: The comment on `vp_extensions` says the list was "checked by running it over one file of each". But `learnings.md`'s probe list (`.js … .markdown`) has no `xhtml` or `pcss`, and the array includes both. Extra entries can only add a check, so this is harmless. Still, either drop the two extensions or change the comment to say which entries were probed and which come from oxfmt's linguist table.
