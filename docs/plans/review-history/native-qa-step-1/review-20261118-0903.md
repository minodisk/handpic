### Findings

1. **crates/backend/src/mcp.rs:1591**: The `screenshot` tool's `description` is one source line with runs of nine spaces at each place where a line break was lost ("in         device pixels", "(1568 by default,         256 to 4096)", "Present only in a         build", "after         another tool"). Every other tool description in this file wraps with a trailing `\` continuation, which drops the newline and the next line's leading whitespace, so this is the only description that sends padded whitespace to MCP clients in `tools/list`. rustfmt does not touch string contents, so no linter will catch it. Fix: split it over several lines with `\` at each line end, the way `get_view` / `get_preview` do (for example `"A debugging aid: Handpic's window as a PNG of its last drawn frame, in \` / `        device pixels, ...`).
2. **docs/plans/20261118-native-qa/learnings.md:9-12**: The second bullet says `with_screenshot` "composes with `with_all_tools` in either order", and then says `with_all_tools` "replaces the router". The second statement is the correct one. `with_all_tools` sets `tools: Companion::tool_router() + Companion::native_router()` and drops anything added before it, so `Mcp::new(..).with_screenshot().with_all_tools()` does not list `screenshot`. Step 2 relies on these notes, so the contradiction is a trap. Fix: state that `with_screenshot` must come after `with_all_tools`, because `with_all_tools` replaces the router and would drop the tool. Keep the point that `Mcp::new(..).with_screenshot()` alone lists eight tools.
