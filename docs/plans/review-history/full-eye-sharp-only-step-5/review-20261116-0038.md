### Findings

1. **[crates/backend/src/index.rs:628-654]**: The supported-version list in `Index::migrate` now has `22, 24, SCHEMA_VERSION` and still leaves out `23`, so a v23 database is rejected with `unsupported index schema version 23`. v23 is not a hypothetical version. It is the schema of the released v1.8.0, v1.9.0 and v1.10.0 (`git grep 'const SCHEMA_VERSION' v1.10.0` gives `23`). The gap first appeared on main when #946 bumped 23 to 24 without listing 23, and this PR edits the same list and repeats the omission. Every migration block already covers 23: `(10..24)` adds `full_eye_sharp` and the new `(16..25)` drops `eye_focus`. The schema comment this PR adds also says "a v16 to v24 database drops it in place". In practice, a user upgrading from v1.10.0 gets `Index::open` failing. The Tauri app then logs it and runs with no index (`crates/app/src/main.rs:740`), and the native app returns an error (`crates/native/src/main.rs:5265`). Fix: add `23` to the list, and add a migration test like `a_v24_database_drops_the_in_focus_probability_...`. The test should build a v23 database (with `eye_focus` added, `full_eye_sharp` dropped, `user_version = 23`), assert that it opens at `SCHEMA_VERSION` with the same columns as a new database, and confirm that the files, ratings and `last_viewed` are kept.
