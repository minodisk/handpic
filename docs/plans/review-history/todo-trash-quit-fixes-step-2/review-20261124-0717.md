### Findings

1. **[docs/plans/20261123-todo-trash-quit-fixes/learnings.md:41-42]**: The note says the `ClearFlow::idle` guard makes the new `drain_clear` call a no-op "where the dialog only steps aside (an import set aside, ...)". That is wrong for the import's `Dismiss::Aside` branch. `dismiss_folder_dialog` sets `self.folderops.aside = self.folderops.dialog.take()`, so `folderops.dialog_open()` is false. An import run does not enter `gate.in_flight()` either (only the sidecar, date-folder and rename runs and the trash runs do). So `up` and `busy` are both false, and a held clear runs right away while the import's copy is still going. The code's behavior is acceptable: the import never touches the index, and once the dialog is out of the way this is the same as any other idle point. Only the learnings sentence misstates it. Fix: drop "an import set aside" from the no-op list, and say instead that an import set aside lets a held clear go on because its run does not hold the index. Only the Cancel of a running import or sequencing, whose dialog stays open until the run ends, is a no-op.
