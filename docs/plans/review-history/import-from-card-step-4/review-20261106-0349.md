### Findings

1. **crates/app/ui/src/import.ts:110 (`importNote`)**: The note says `NOTHING_TO_COPY` ("Nothing left to copy: every dated file is already there.") whenever `totals.copyCount === 0`. That is wrong in two cases. (a) A folder with no RAW or JPEG under it, such as the wrong folder right-clicked or a card's root whose `DCIM` is hidden or empty, has nothing "already there". (b) A source whose dated files all collide has nothing "already there" either: the collision list right below says they are at the destination with another size and were not copied. Base the note on what the preview holds. With no folders and no undated files, say no photos were found under the folder. When `skipped === 0` but collisions or undated files exist, do not say "already there". Add a test for each case in `import.test.ts`.
2. **crates/app/ui/style.css:1376 (`#import-box p:empty, ...`)**: `#import-rows` is not hidden when empty. On a refused preview or a source with no photos, `folderRows` returns nothing, and the dialog shows an empty muted, padded block (`#import-rows` has `background: var(--muted)` and padding). `#sidecar-rows:empty` already handles this for the sidecar dialog. Add `#import-rows:empty` to the `:empty` rule.
3. **crates/app/ui/src/main.ts:1630 (`importFrom`)**: Nothing is shown between choosing `Import…` and the preview's return. `import_preview` reads the head of every file on the card, which on a slow card with hundreds of files takes seconds, and a second `Import…` in that time is silently ignored (`importFlow.start` returns false). Set a status note while `importFlow.phase === "previewing"`, for example by setting `importing` to a "reading <dir>…" line and calling `renderMeta()`, and clear it in the preview's `then` and in `failImport`. That way the user can see the click was taken.
