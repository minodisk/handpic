### Findings

1. **crates/app/src/folderops.rs:1284**: The new `self.request_prefetch(cx)` went into the `Err` arm of `date_folder_ran` (the `Rename by Capture Date…` run), not the `Err` arm of `rename_ran` (around line 2124), which the plan, `docs/agents/app.md` ("`rename_ran`'s `Err` arm") and `learnings.md` all describe. The date rename never calls `folderops.renames.start`, so `renaming()` never blocked a prefetch there and the added call is outside this step's scope. Meanwhile a failed tree rename still ends in `settle_folder_run` with no prefetch request, so a prefetch refused while that rename was in flight is never asked for again and the ring stays empty until the next page turn. This misses the "after a failed one explicitly" criterion. Fix: move the call from `date_folder_ran` to `rename_ran`'s `Err` arm, after `settle_folder_run`. Also consider adding a UI test for the failed-rename path, for example a rename refused because the target name already exists, followed by an assertion that the ring fills again. Neither current test exercises this path, which is why the misplacement went unnoticed.
2. **crates/app/src/main.rs:4510 / crates/app/src/folderops.rs:1362**: `renaming()` is true for any folder rename in flight, including a rename of a tree folder that is neither the open folder nor one of its ancestors. A successful rename like that goes through `folder_renamed`'s `None` arm into `settle_folder_run`, which neither reopens nor asks for a prefetch (unless a resync was waiting). Take the case where the current preview's read or the last prefetch settles while such a rename is in flight. The refused `request_prefetch` is never retried, so the ring stays idle until the user pages. The docs' claim that "a successful one reopens the folder, which refills the ring" only holds when the open folder moved. Fix: either scope the guard to renames that affect the open folder (`self.dir` blocked by `self.folderops.renames.blocks(dir, IGNORE_CASE)`), which is the only case where a read can hold a file inside the renamed folder, or call `request_prefetch` in `folder_renamed`'s non-reopen arm as well. Update the doc wording in `docs/agents/app.md` to match.
