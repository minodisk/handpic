### Findings

1. **[crates/core/src/arw.rs:754-760]**: The two paths that take the note's `PreviewImage` guard it differently. `FarNote::take` refuses a JPEG that runs past the end of the file and keeps the strip. The in-buffer branch (`else if fallback`) calls `take_note_preview` with no range check at all, and the test `a_leica_note_preview_is_taken_over_a_thumbnail_strip` relies on that: its `buf` ends before the JPEG it accepts. Through the reader, a thumbnail-only Leica DNG whose note sits inside the 1 MiB prefix but whose 0x0300 points past EOF (a truncated copy or a bad offset) now fails with `preview out of range`: the ranged read is refused, the whole-file retry gives the same `Embedded`, and `embedded_from` errors again. Before this change the same file showed its 160x120 strip. The in-buffer branch is also what `parse` runs on a whole-file buffer, so this hits the retry path too. Fix: keep the end-of-file check in one place. For example, hand back a `FarNote` whenever `leica && fallback` (not only when the note runs past `buf`), so `reader::take_far_note` always applies the `file_len` check. The extra 4 KiB read only happens on thumbnail-only Leica DNGs. Alternatively, have `parse_noted` take the note JPEG only when it ends within `buf` and otherwise leave the decision to the reader. Then add a test where the note is inside the prefix and its JPEG is past EOF, and assert that the strip is kept. Also adjust the `raw-metadata-parsing.md` rule ("unless it runs past the end of the file") so it covers both paths.
