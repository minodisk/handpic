### Findings

1. **[crates/app/src/commands.rs:3020-3021]**: Removing `rank::Frame::eye_focus` breaks the build of the Tauri app's tests. The `rank_dump_of_real_folders` test reads `f.eye_focus` from `row.frame` (a `rank::Frame` from `Index::rank_rows`), and `cargo check -p riffle-app --tests` now fails with `error[E0609]: no field 'eye_focus' on type '&Frame'` at both lines. The root `cargo test` in `mise.toml` (lines 95 and 136) and `.github/workflows/ci.yml:167` compiles that test, so `ci:local` and the PR checks will fail. The Step 4 done-when has two conditions that cannot both hold: "`Frame` has no `eye_focus`" and "No file under `crates/app` changes". The plan puts this exact compile-only edit in Step 5 ("the debug dump in `crates/app/src/commands.rs` (the TSV header near line 3009) no longer prints `state` / `eye_focus`"). Suggested fix: move that one compile-only edit into Step 4. Drop the `state` and `eye_focus` columns from the header at line 3009 and from the `writeln!` at lines 3014-3021. Amend the plan's Step 4 / Step 5 and the decisions list to match, and confirm this with the user, because it touches the frozen Tauri app. The alternative is to keep `eye_focus` on `rank::Frame` (filled by `rank_rows`, never read by `tech`) until Step 5, but that contradicts Step 4's own done-when.
2. **[crates/cli/src/facechoice.rs:165, 251-253, 182-192]**: `facechoice --check` now compares `af_rule` (the judged face's `full_sharp`) with `scan::extract_analysis(..).full_eye_sharp`, but the two are not computed under the same condition. The scan's `full_eye_sharp` (`crates/core/src/scan.rs:313-316`) returns `None` unless `has_larger_jpeg(arw)`: it needs an `arw.full` that is not the preview's offset and is not HEVC. `facechoice` measures on whatever `reader::read_full` returns. For a RAF (its one embedded JPEG is both preview and full), for any file whose full JPEG is its preview, and for an HEVC CR3, `facechoice` reports a value where the scan stores `None`. Every such file would be counted as a `mismatch`, so the check is not usable on those folders. Suggested fix: apply the same gate in `frame()`. For example, make `scan::has_larger_jpeg` public (or move it next to `read_full`) and set `full` to `None` when the read `Arw` has no larger JPEG. A unit test for the gated case would help, since the learnings note the check was not run on real files.
