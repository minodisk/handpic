### Findings

1. **crates/native/src/overlay.rs:50-53 (`Marks::toggle`)**: Turning the overlay off keeps `focus`, and while it is off nothing re-reads it (`read_focus` returns early, so the pass 1 / pass 2 messages that name the current file are ignored). When the overlay is turned back on, `toggle_marks` starts a new read and calls `cx.notify()` straight away. If the current file is the one the last read was for, that frame's `Marks::mark` uses the old `Focus`. Example: press `f` off on file A, let pass 2 reach A, then press `f` on. The mark first shows the stale color (white) and only turns green or gray when the new read comes back. The same thing happens after paging away from A and back to it while the overlay is off. The plan says the mark must reflect the stored analysis and must not draw stale data (only the latest read is kept). Fix: clear `self.focus` when `toggle` turns the overlay off, so after turning it on nothing is drawn until the fresh answer arrives. Do not clear it in `reading()`, because the re-reads triggered by pass messages would then make the mark blink off. Add a `Marks` test: answer for "a", toggle off, toggle on, and assert `mark(Some("a"))` is `None` until a new `answer`.
