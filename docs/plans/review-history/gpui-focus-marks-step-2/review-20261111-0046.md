## Round 1

**Reviewed commit**: `fac3bd356f1e3d04f80d6e8d29052e4730965e80` feat(native): draw the f focus mark colored by the stored analysis

STATUS: NEEDS_FIX

### Findings

1. **crates/native/src/overlay.rs:50-53 (`Marks::toggle`)**: Turning the overlay off keeps `focus`, and while it is off nothing re-reads it (`read_focus` returns early, so the pass 1 / pass 2 messages that name the current file are ignored). When the overlay is turned back on, `toggle_marks` starts a new read and calls `cx.notify()` straight away. If the current file is the one the last read was for, that frame's `Marks::mark` uses the old `Focus`. Example: press `f` off on file A, let pass 2 reach A, then press `f` on. The mark first shows the stale color (white) and only turns green or gray when the new read comes back. The same thing happens after paging away from A and back to it while the overlay is off. The plan says the mark must reflect the stored analysis and must not draw stale data (only the latest read is kept). Fix: clear `self.focus` when `toggle` turns the overlay off, so after turning it on nothing is drawn until the fresh answer arrives. Do not clear it in `reading()`, because the re-reads triggered by pass messages would then make the mark blink off. Add a `Marks` test: answer for "a", toggle off, toggle on, and assert `mark(Some("a"))` is `None` until a new `answer`.

### Fixed

1. `Marks::toggle` now clears `focus` when turning the overlay off; added a `Marks` test for off/on without a fresh answer.

## Round 2

**Reviewed commit**: `23c8c8b149a1f15b2cb89f50463ddaff24be67dc` fix: address local review round 1 findings

STATUS: NEEDS_FIX

**Previous feedback**: addressed 1 / dismissal accepted 0 / re-raised 0

### Findings

1. **crates/native/src/overlay.rs:52-58, 71-77 (`Marks::toggle` / `Marks::answer`)**: The Round 1 fix clears `focus` when the overlay turns off, but it leaves `read` alone. A read already in flight can still answer after that, because `answer` only compares tickets and does not check `on`. Here is the sequence: `f` on starts a read for A (ticket N). `f` off clears `focus`. The read for N comes back and stores A's focus while the overlay is off. Pass 2 then reaches A, and that message is ignored because `read_focus` returns early while off. `f` on starts ticket N+1, but until N+1 answers, `mark(Some("A"))` draws the stale color, which is the same problem Round 1 item 1 described. The window is narrow (one read's duration), but the fix is one line. In `toggle`, also bump `self.read` when turning off (or have `answer` drop the result while `!self.on`), so a read started before the toggle can never be kept. Extend `no_stale_mark_after_toggling_off_and_on` (or add a test): take a ticket, toggle off, `answer` with that ticket, toggle on, and assert `mark(Some("a"))` is `None`.

### Fixed

1. `Marks::toggle` now also bumps `read` when turning the overlay off, so a read in flight is dropped by `answer`; added a test for it.
