### Findings

1. **crates/native/src/theme.rs:296-319 (`apply`)**: going back to Neutral does not restore it exactly, which the plan requires ("switching back to Neutral must restore it exactly"). `Theme::apply_config` (gpui-component 0.9.1 `schema.rs:1120`) only writes `theme.shadow` when the config sets it (`if let Some(shadow) = config.shadow`). Hybrid, macOS Classic, Mellifluous and Molokai set `"shadow": false`, and `Default Light` / `Default Dark` (`default-theme.json`) and the other shipped themes leave it unset. After the user picks Molokai and then Neutral, or any shipped theme that leaves shadow unset, `shadow` stays `false` until restart, so `Button` and the other elevated surfaces lose their shadows. The result depends on which theme was picked before. Fix: in the first `Theme::update` that fills the slots, also reset `theme.shadow = true` (the `Theme` default, `theme/mod.rs:785`) before `Theme::change`. `change`'s `apply_config` then overrides it only for the themes that set it. Add this to learnings.md's Step 3 note on `shadow`. Check the same way for any other field `apply_config` writes only when set (`highlight` included, although the app draws no code view today).
2. **crates/native/src/settingsview.rs:891-893**: the new `themes` function went in between `commits` and its doc comment. `themes` now has the doc "Enter or the focus leaving a field commits it." followed by its own text, and `commits` has lost its doc.
