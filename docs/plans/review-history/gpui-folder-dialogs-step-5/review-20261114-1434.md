### Findings

1. **[crates/native/src/folderops.rs:90 / crates/native/src/main.rs:3697-3705]**: The pane draws one note line chosen by priority: `trashing`, then `folderops.note()`, then `gate.waiting()`. `note()` now falls back to `importing` and then `imported`. That means the import's lines hide the `<label>: waiting for the scan to finish` line. This is a regression in a common path. `imported` stays until the next folder open, and the run opens its first date folder, which starts a scan. If the user presses Move to Trash or Delete during that scan, the operation is held, but the pane keeps showing `Imported n files (...)` and never says the operation is waiting. The same happens during the run, when `importing n / m` hides the waiting line. A trash run's `trashing` line also hides the import result while it runs. The Tauri `renderMeta` appends `sequencing`, `trashing`, `importing`, `imported` and the idle-gate waiting line as separate lines, so none of them hides another. Suggested fix: draw `importing` / `imported` as their own line(s) next to the existing one, not as a fallback in that `or_else` chain. For example, keep `note()` for `sequencing` and add an accessor for the import lines that the pane renders separately. Alternatively, at least put `imported` after `gate.waiting()` in the chain.
