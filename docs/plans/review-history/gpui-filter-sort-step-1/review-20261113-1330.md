### Findings

1. **crates/native/src/main.rs:788-800 (`refilter`)**: when a rebuild moves the current file to another index but it stays current (`moved == false`), the status line keeps the old position. `self.status` (`"{index + 1}/{len}  name ..."`) is only written in `loaded`, and `refilter` sends no new request when `shown == current_path()`. Two common cases hit this. On a fresh index under `"capture"`, pass 1's `Done` moves the current file (for example from 1 to 6 in the learnings' HX95 run), but the status still says `1/6`. Under `"rating"` with auto-advance off, a star key does the same. The pane's `n / total` is correct because `shown`'s `at` is remapped, so only the status line goes stale, even though native-app.md says the status line indexes into `files`. Fix: in `refilter`, rewrite the `n/total` prefix after the rebuild. Either rebuild the status from `shown` and its remapped `at`, or keep the per-file part of the status separate from the index and format `at + 1 / files.len()` when the status is drawn, as `meta_pane` does.
2. **crates/native/src/main.rs:1085 (`store`'s failure path)**: a failed store's revert calls `refilter(current_path, true, ...)` and keeps the scroll. The Tauri `send`'s `.catch` calls `refilter()` with the default `keepScroll = false`, so it scrolls the current file into view, as `commit` does. native-app.md's scroll rule covers only the judgment and step (scroll) and `Done` / re-listing (keep) cases, so this difference is neither ported nor documented. Pass `false` to match the Tauri revert, or keep `true` and add the revert to the rule in `docs/agents/native-app.md` with the reason.
