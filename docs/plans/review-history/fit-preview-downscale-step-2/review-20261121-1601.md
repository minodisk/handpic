### Findings

1. **[crates/app/src/main.rs:4533 (`prefetched`) / 4862 (`fit_settled`)]**: A prefetch that is in flight when the canvas settles larger escapes the check. It was decoded for the old canvas. `fit_settled` runs `Ring::release` over `held` only, and `request_prefetch` gets `None` from `next()` while `pending` is set. When the read arrives, `settle` puts the undersized image in the ring and nothing checks it again. On the next page turn onto that neighbour, `show_held` paints it upscaled (soft) and `show_current` -> `refit` reads the file again. That turns a prefetch hit into a soft frame plus a full re-read, which is the cost the ring is there to avoid. It is easy to hit while dragging the window larger and then paging. Fix: in `prefetched`, after `settle`, run the same release `fit_settled` uses (`ring.release(|held| !fitscale::serves(decoded_size(&held.image), held.upright, self.viewport.get()))`) and pass the result to `give_up` before `request_prefetch`, so the entry is read again at the current scale. Do not filter the `held` to `None` before `settle`, because `settle(None)` puts the path in `refused`. Then reword the docs/agents/app.md sentence "a ring entry ... decoded for an older canvas is re-read when shown" to match.
