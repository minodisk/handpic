1. **crates/app/ui/src/main.ts:1525**: A split's per-file failures are reduced to a count (`splitStatus` only appends "N files failed"), and `ran.failed`'s paths and messages are dropped. The user cannot find out which files did not move or why. The backend returns them on purpose (plan Step 3: "the failures with their messages"), and every other multi-file run in `main.ts` puts them in the error list: `trashed` (`errors.add(path, \`${baseName(path)}: could not move to the Trash: ${message}\`)`) and `finishSequence` (`errors.add(failure.path, failureText(failure))`). Fix: before `setStatus(splitStatus(...))`, loop over `ran.failed` and call `errors.add(path, \`${baseName(path)}: could not move: ${message}\`)` (or similar wording), then `renderMeta()` if the error list needs it. This keeps the status line as the summary and the error list as the detail, the same as the trash and sequence runs.
