### Findings

1. **[crates/engine/src/rename.rs:178-186 (`shared_xmps`)]**: On a case-insensitive file system (Windows, macOS), mates whose stems differ only in case are not detected as sharing. `existing_sidecar` returns early with `wanted` spelled from each RAW's own stem whenever `wanted.exists()`. So for `a.ARW` and `A.NEF` next to one `a.xmp`, it gives `…\a.xmp` for the first and `…\A.xmp` for the second. Those are two different `PathBuf` keys (Path equality is case-sensitive), so each key has one RAW and `retain(len > 1)` drops both. The split then falls back to the old bug: `a.xmp` moves with whichever RAW goes first, and the other RAW loses it. `file_plan` has the same problem. The plan says this definition "covers the case-insensitive fallback", and the grouping by lower-cased name shows that was the intent, but the keying breaks it on the primary platform. Fix: inside each lower-cased-name group, key by the on-disk entry, not by `existing_sidecar`'s spelling. For example, canonicalize the returned path, or use the group's real directory entry found with `eq_ignore_ascii_case`, as the fallback does. Then use the same key for the `contains_key` lookup in `file_plan` and the `xmp_of` lookup in `split`. Add a test with mixed-case mates (`a.ARW`, `A.NEF`, `a.xmp`) that asserts both date folders get the `.xmp`.
