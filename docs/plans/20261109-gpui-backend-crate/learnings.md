## Step 2

- Test counts on Windows: before 476 (394 in `riffle-app` + 82 in `riffle-backend`); after 277 in `riffle-app` + 199 in `riffle-backend` = 476. The sum holds. The plan's 212 in the backend is textual; the moved modules bring 117 tests here, not 120, since `#[test]`s under platform gates do not run on Windows.
- `#[cfg(test)]` does not cross a crate boundary: the backend's `cfg(test)` is off when `riffle-app`'s tests are built, so two things the app's tests used did not move as plain renames.
  - `Index::row_flags` and `RowFlag` (used by `foldersidecars.rs`'s tests) lost their `#[cfg(test)]`, the smallest edit that keeps them shared. They are `pub`, so no dead-code warning, and they ship in the library.
  - `index::tests::jpeg_with_exif` (used by `commands.rs`'s tests) was copied alone into `commands.rs`'s test module, on top of the `gradient_jpeg` helper already there. The backend needs `mozjpeg` as a dev-dependency for the `jpeg` helper in its own `index.rs` tests, which the plan's "adds nothing" did not foresee. A dev-dependency of a path dependency is not resolved in the native workspace, so `crates/native/Cargo.lock` did not change.
- `index.rs`'s `pub(crate) mod tests`, `jpeg` and `jpeg_with_exif` stay `pub(crate)`: no app code reaches them now.
- `crates/app/src/main.rs` no longer names `photolab`: `sidecar` was its only user in the app, so keeping the `use` warned as unused.
- `rusqlite` is gone from `crates/app/Cargo.toml`: nothing left in `crates/app/src` names it. The tests that reach `index.conn` only call its methods. Root `Cargo.lock` diff: `rusqlite` leaves `riffle-app`, `mozjpeg` joins `riffle-backend`; no version change.
- Tauri smoke check: **not performed.** `mise run tauri:dev` runs the debug build under the same identifier `com.minodisk.riffle` as the installed app, so even a launch opens the user's real index and a judgment or Clear Cache there is off limits. The folder for it is ready at `D:\Photos\tests\20261109-backend-index-sidecar` (three real copies, no hard links). See the pending manual check below.

## Step 3

- Test counts on Windows (`cargo test -- --list`): before 476 (277 in `riffle-app` + 199 in `riffle-backend`); after 214 in `riffle-app` + 262 in `riffle-backend` = 476. The sum holds; 63 moved. The plan's 280 is a textual count including platform-gated tests.
- Departures from a pure move, all small:
  - `listing.rs` also holds `folders::kind`, which `is_file` calls and the plan did not name. `folders.rs` re-exports it with `pub(crate) use` so `import.rs`'s `folders::kind` is unchanged; `commands.rs` re-exports `canonicalize`, `read_listing` and `stat_sidecars` the same way for `datefolder.rs`, `foldersidecars.rs`, `import.rs` and `rank.rs`.
  - `folders::is_file` no longer exists in the app (its only caller, `read_listing`, moved with it).
  - Inside `listing.rs`, `crate::folders::Media::default()` / `crate::folders::is_file(` became `Media::default()` / `is_file(`, and the `Listing` doc's `folders::Media` became `Media`. `read_listing` is otherwise byte-identical.
  - `output.rs`'s doc comment names `listing::is_file` instead of `folders::is_file`; `docs/agents/tauri-app.md` and `docs/agents/photolab.md` likewise (`listing::canonicalize`).
  - `trash::sidecars_of` and `output::outputs_in` became `pub`. `sidecars_of` was the only `pub(crate)` in `trash.rs`.
- `crates/app/Cargo.toml`: `objc2-foundation` and `percent-encoding` left with their macOS target section (only `trash.rs` used them); `trash` stays too, since `commands.rs` calls `::trash::delete` and `os_limited` directly, and `crates/backend/Cargo.toml` gained it with the same spec lines. Root `Cargo.lock`: dependency-line moves only, no version change.
- `crates/native/Cargo.lock` gained `trash 5.3.0` and `urlencoding 2.1.3` through `cargo`; nothing became a duplicate. `trash` resolved to 5.3.0 there and stays 5.2.9 in the root lock: the spec line is the same, the native lock had no entry to hold it, and no `cargo update` was run. The native crate does not call `trash` yet.
- Log targets: the panic hook's line is now under `riffle_backend::diagnostics` (`docs/agents/app-log.md` updated); `log_frontend` stayed in the app, so `uncaught-js:` keeps `riffle_app::diagnostics`; `invariant!` is expanded at the call site, so its lines keep `riffle_app::commands`. `tauri_plugin_log` is configured by `.level` alone, with no per-target filter, so nothing is dropped. `trash.rs` and `output.rs` do not log.
- The `panic:` and `invariant:` prefixes after the move were checked with a throwaway scratch binary depending on `riffle-backend` by path, using its `install_panic_hook` and the `invariant!` macro through its re-export: `[riffle_backend::diagnostics][ERROR] panic: thread=main location=src\main.rs:14:41 payload=boom` and `[hook][WARN] invariant: scan progress within total: done=3 total=2`.
- A corrupt `.ARW` does not reach the panic hook, so the smoke check's expected `panic:` line cannot appear. mozjpeg 0.10's error handler ends in `std::panic::resume_unwind` (`errormgr.rs:58`), which skips the hook, and `riffle-cli` confirmed it: both a garbage preview (SOI kept) and a non-JPEG preview give `Error: libjpeg fatal error: ...` and no `panicked at` line, as `scan` errors. See the deferred item below.
- `commands.rs` / `folders.rs` / `output.rs` / `diagnostics.rs` at the old paths: `crates/app/src/output.rs` and `diagnostics.rs` are new thin files, so git shows them as modified or added beside the rename rather than as a clean rename of the old path.
- PR #957 (rename-to-handpic Step 2) edits two comment lines of `crates/app/src/diagnostics.rs` (`Riffle.log` → `Handpic.log`): one in the module doc, now in `crates/backend/src/diagnostics.rs`, and one on `log_frontend`, which stayed in the app. Whichever lands second re-applies them by hand. No other session was changing the moved files (`git worktree list` plus `status --short` for each).
- Tauri smoke check: **not performed** (same reason as Step 2: the debug build shares the real app data, and this one moves real files to the Trash). The folder is at `D:\Photos\tests\20261109-backend-trash-output`. Pending manual check below.
