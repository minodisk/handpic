# Learnings: Windows real-device checks through MCP and screenshots

## Step 1

- **What MCP plus `screenshot` can close.** The companion's tools (`open_folder`, `navigate`, `set_overlays`, `set_judgment`, `set_filter`, `set_settings`, the folder-operation tools, `undo`, `wait_for_idle`, `get_status`) and the `screenshot` tool, with a few synthetic left clicks, closed the boxes that need only an open, a navigation, a setting, a confirmed run or a left click. They cannot close what needs a key press (Tab / Escape in a dialog, `Ctrl+Z`, a held `→`), the IME, a drag (the strip's height), a right-click, a HiDPI display, or macOS / Linux. A run confirmed through MCP with `mcpAllowDestructive` opens no dialog, so the dialog's keys and dimmed buttons stay open too. Visual points (colors, legibility, the text size) still need the user's judgment from the running window; the screenshots only let an agent see the layout and the text.
- **Setup worth keeping** (from `results.md`): a fresh `--index`, `--settings` and `--log` per launch, `--mcp-port` fixed for the client, `{"mcpEnabled": true}` (plus `"mcpAllowDestructive": true` where a run must be confirmed without a dialog) through `--import-settings`. Git Bash mangles `\\` in JSON arguments even through stdin here-strings; the client took `D:/...` paths and converted them to backslashes.
- **Pass 2 commits rows in batches of 10** (`BATCH`, `crates/engine/src/index.rs`), so in a folder under 10 files the `Analysis` group and the strip's face icons appear only when pass 2 ends. Expected; a check of "appears without input" needs a folder of more than 10 files.
- **Decisions on sub-points the run did not name** (see the plan's rule section): the `f` overlay boxes 1 and 2 and the catalog icons' Windows box were closed on the user's by-eye judgment; `todo-three-decisions` box 1 was closed on the 2026-11-22 sight of the sort menu's opening; `native-meta-analysis` box 1 was closed on the list of rows the group held; the `native-themes` boxes 1 and 2 were narrowed, not deleted, since the themes were set through MCP and the dialogs, the settings box and readability were not seen.
- **Findings A to D became four `todo.md` items**; the three `docs/agents/app.md` rules were marked seen, the middle-ellipsis rule at the default strip height only, and their section headings keep `(Inferred)`.
- **Finding E was not applied to `todo.md` (plan list B).** The item it was to extend (`App: Rewrite Sidecars from Index reported "4 files not in the index (skipped)" in a fully scanned folder`) had been removed by #1253 (`eb658f99`), merged after the run's `3918064c`, which reworded the row to `N files with no judgment on record (skipped)`. The run reproduced the old wording on the old build, and the new wording's on-screen check is already a box of the `todo-four-display-fixes` item in `todo.md`, so nothing was added. The plan's list B records this. Lesson: a run's results can go stale against `main` before they are applied; check each anchor still exists after the rebase.
- **`results.md` stays in this folder** as the run's record, copied with LF and without the Japanese gloss of finding C. The removed and narrowed boxes live only there, in the items' background sentences and in the PR description.
- A Bash `python -` with no stdin hangs the tool call until killed; run scripts as files with `mise x -- python -I <file>`.
