# Todo measurements: close out the measurement and check items on Windows

## Purpose

`todo.md` holds a batch of items that ask only for a measurement or a check on
a real host and a note of the result in a guide. They have stayed open because
each needs a host with the real data, an NVMe drive or the running app. This
plan runs them on the Windows 11 host (C: is the NVMe `CT1000P5PSSD8`, D: the
SATA SSD `CT4000BX500SSD1`), records every result in the doc the item names
and in this folder's `learnings.md`, and deletes the finished items (or
finished boxes) from `todo.md`. What needs a human's hands (a real keyboard,
clicks the MCP companion cannot drive, by-eye judgments) stays in `todo.md`,
reworded to what is left. No source code, lock file or constant changes: a
finding that suggests one is recorded as an open question.

The `todo.md` headings in scope (and no other):

1. `Engine: measure whether a notify watch blocks deleting a folder on Windows`
2. `Engine: re-check that notify 8.2.2 still queues configure behind Unwatch when the app starts using watch`
3. `App: measure the scan's read cap on NVMe`
4. `App: measure the scan pause in load with presses on files pass 1 has not read yet`
5. `Docs: the "Focus candidate pass" numbers in docs/humans/performance.md are missing the app's own scan/faces log lines`
6. `Dev setup: check that a plain mise install adds rust-analyzer to an already installed toolchain`
7. `App: check the upstream licenses of the shipped gpui-component themes before packaging (native-themes)`
8. `App: real-device checks of the strip's sort order, the filter and the filter / sort menus` and `App: real-device checks of the EXIF filter sections and the refilter fixes`: only the boxes (or parts of boxes) the MCP companion can verify.

## Trade-offs and risks

- **One step or several.** Everything here is measurement plus docs, so this is one PR (decided at approval). The cost: the items are unrelated, the PR touches seven docs and nine todo headings, and a slow or blocked measurement holds back the finished ones. The mitigation: an item that cannot be completed is narrowed in `todo.md` rather than blocking the PR.
- **Item 5's folder is gone.** The todo and `performance.md` name "the 2134-file Sony folder" `2026-09-19`; on disk it now has 282 ARW. Option (a), chosen: record the app's lines for a copy of today's 282-file folder, say so in the doc, and add a `handpic-cli scan` run of the same copy. Not comparable with the 2134-file CLI table, and the doc says so.
- **Item 8: state through MCP against the drawn menu and the real key.** MCP verifies the filter's state, `filter_offers` and (by screenshot) the strip, meta pane and status bar, but cannot open the `Filter ▾` popover, and `set_judgment` is not a physical `p`. Decided: delete the boxes whose state and screenshot are both verified, and narrow the others to the by-eye remainder.
- **Item 3 may argue for another `READ_SLOTS`.** If cap 2 costs pass 1 throughput on NVMe, the choices are a per-drive cap, a higher fixed cap (which costs the SATA preview wait measured earlier: 14-16 ms at 2, 20-25 ms at 4, 29-57 ms at 8) or leaving it. Not decided here; the numbers go in the guide and the todo item becomes the decision.
- **Item 2: which lock is right.** Confirming the queuing on 8.2.2 closes the todo as worded, but CI still runs the `treewatch` tests only on the root lock's 8.2.0. Pinning `crates/app/Cargo.lock` to 8.2.0, or moving the root lock to 8.2.2 so CI covers the shipped version, is a lock change outside this plan; if the re-check fails it becomes necessary and is left as an open question either way.
- **Item 6 touches shared toolchains.** Removing `rust-analyzer` breaks the LSP of every session on the host until it is back, and a concurrent `cargo` in another worktree could see rustup mid-change. The window is short and the step always restores the component. If a plain `mise install` is not enough, where a `mise install --force rust` line belongs is left open.
- **Item 7 can find a problem in a shipped release.** 2.0.1 already ships the 21 themes with only gpui-kit's Apache-2.0 notice. Adding missing attributions fixes future packages; a theme with an incompatible or undeterminable license needs a decision (drop it, replace it, ask upstream) and possibly a release, none of which this plan makes.
- **Cold-run cost and disk wear.** Items 3 and 4 need a fresh unbuffered copy per run of a folder large enough to keep pass 1 running through several probes; that is tens of GB per run on a C: that is about 80 % full. Fewer runs mean weaker p95s; the step asks for at least two per variant and for the probe counts to be reported so the reader can judge.
- **The patched builds are not the shipped binary.** Cap 22 and pause off are one-line patches on the release build and are recorded with their commit, but they are scratch builds; the numbers describe those builds on this host on that day.
